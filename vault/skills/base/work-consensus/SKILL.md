# 工作共识预载

本技能是全局共识的可调用版本。开工前调用本技能，然后按以下流程执行。

## 核心原则

1. **深模块优先**：每个模块 = 简单接口 + 丰富实现。宁可少而深，不要多而浅。
2. **Deletion Test**：删掉模块后复杂度消失 → 是 pass-through，删；复杂度散落到 N 个调用方 → 它在隐藏复杂度，留。
3. **接口是测试面**：测试锁死对外行为，实现交给 AI；测不动说明接口设计有问题。
4. **真接缝才有抽象**：只有一个实现的接口是虚假抽象，删掉；出现第二个实现再抽。
5. **文件系统是模块地图**：目录/命名反映功能边界；模块顶部渐进式披露：是什么 → 怎么用 → 类型/接口 → 实现。
6. **AI 是每天入职 20 次的新人**：没有长期记忆，只能靠结构、命名、接口、测试理解系统。先修结构，别用 prompt 救结构。

## 预载流程

1. 读 `~/.dsh/AGENTS.md`（若尚未在上下文中）。
2. 读当前工作区/项目 `AGENTS.md` / `CONTEXT.md`。
3. 画模块地图：列出外层入口、稳定接口、易变实现。
4. 对可疑模块跑 Deletion Test，列出深模块候选。
5. 一次只深化一个模块，测试保护，做完跑测试并观察，再进入下一个。

## 重构检查表

- [ ] 我已知道本模块的公开接口（类型/命令/配置/错误/顺序）。
- [ ] 公开接口已经有测试锁定行为。
- [ ] 我删掉过所有能找到的 pass-through 包装。
- [ ] 我没有为“未来可能”保留单实现抽象。
- [ ] 目录/命名能让新人从文件树看出这个模块在做什么。
- [ ] 修改后跑完了测试/类型检查/构建，并提交了可回滚的一步。

## 来源

基于 Matt Pocock《Why Your Codebase Matters More Than Your Prompt》与 John Ousterhout《A Philosophy of Software Design》的深模块思想整理。
