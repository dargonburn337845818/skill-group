# AI 行为与文件管理规范总册

> 完整规则与依据见本目录 `CONSENSUS.md`；来源见 `SOURCES.md`。
> 核心判断：**AI 缺的不是更多信息，而是“可检查的规范”。文件系统就是 AI 的长期记忆与模块地图。**

## 触发条件

- 用户明确要求“给 AI 立规范 / 整理电脑 / 别再乱放文件”。
- 任何会产生文件的动作：新建项目、写脚本、输出报告、下载素材、跑实验、生成中间产物。
- 需要写/更新规范、约定、标准、检查表时。
- 进入一个陌生工作区，需要先判断“该往哪里放东西”时。

## 一句话规范哲学

```text
少而深：只立少数不可违反的硬底线（放哪、叫什么、何时清、不碰什么）；
其余用目录即模块地图 + 检查表自然约束，不用长篇细则救结构。
```

## 文件管理 · 十诫（必须先执行）

1. **先回答再创建**：新建文件前问——它属于哪个项目/主题？叫什么？放哪个目录？多久后清理？
2. **根目录不堆文件**：`~`、`$HOME/work` 根、桌面、下载目录只放“人先看”的入口文件；其他一律进功能目录。
3. **目录=概念，文件名=职责**：目录名是业务边界（`src/`、`tests/`、`data/`、`docs/`、`scratch/`）；文件名是唯一职责（`project-topic-date.ext`）。
4. **命名可预测**：代码/路径用 ASCII kebab-case；文档可用中文但不用空格、emoji、`final`、`final2`、`未命名`、`副本`。
5. **四类物分开**：代码、数据、生成产物、文档必须分目录，数据是资源不是业务逻辑。
6. **临时物只进 `scratch/` 或 `/tmp`**：当日实验/中间结果放临时区，不在项目根留 `a.json`、`tmp.py`。
7. **生成物要可忽略**：构建/输出目录进 `.gitignore`，不在仓库历史里留下几百 MB 产物。
8. **先查重再创建**：同名/同职责文件已存在时，优先扩展或更新，不另起一个“新版”。
9. **不覆盖/删除用户文件**：AI 不得静默移动、重命名、删除已有文件；必须备份 + 说清影响 + 等确认。
10. **会话结束即收尾**：清理临时文件，把有效产物归档到正确位置，更新 `HANDOFF/AGENTS/CONTEXT`，不让下一会话从头找。

## 长期记忆（轻量）与全盘符接管（新增重点）

> 目标是让 AI 跨会话记得“该把文件放哪、哪些盘符已接管、哪些禁区不能碰”，但记忆本身**短、可读、不臃肿**。

### 记忆三件套（不是数据库，是 3 个小文件）

```text
AI_MEMORY.md       # 跨会话高信号记忆：偏好、红线、环境事实、已定决策（≤100 行）
DRIVE_LAYOUT.md    # 盘符账本：每个盘的用途/状态/已接管目录/禁区（≤120 行）
HANDOFF-*.md       # 上次留下的“下一步 + 关键路径”（≤80 行）
```

- **单一事实源**：同一件事只写在一个文件，其他处只放指针。
- **只记会改变动作的结论**：不记完整文件列表、不记工具调用、不记流水账。
- **写入纪律**：每次会话结束最多新增/修改 ≤3 条；90 天未引用就归档或删除；超行数先压缩再写。
- **读取顺序**：`AGENTS.md → AI_MEMORY.md → DRIVE_LAYOUT.md → HANDOFF`，绝不遍历全盘历史。

### 全盘符接管安全协议（危险动作防御）

1. **接管前只读盘点**：先生成目录树/大小/重复/旧文件候选，不修改任何文件。
2. **写账本再动**：每个盘符在 `DRIVE_LAYOUT.md` 登记 `类型 / 状态 / 已接管目录 / 禁区`；未登记 = 未授权。
3. **先 manifest 后执行**：每批 ≤50 项，先列 `before → after`，用户确认后执行。
4. **不自动删除**：只移到 `_trash/` 或 `archive/`，保留 30 天；删除必须用户明确确认。
5. **禁区永不碰**：系统目录、Program Files、AppData、`.git`、`node_modules`、虚拟环境、密钥/证书、`.env`、浏览器/微信/Discord 数据。
6. **不跨盘符乱挪程序**：程序与系统由安装器管理；跨盘只移动文档/媒体/数据/项目资产。
7. **每步可回滚**：记录 before/after + 回滚命令，写 `reports/drive-audit-<date>.md`；异常立即停止。
8. **记忆只更新状态**：整理完后 `DRIVE_LAYOUT.md` 更新状态，`AI_MEMORY.md` 只写一行指针；完整明细进审计文件。

## 目录骨架（默认模板）

```text
~/
├── projects/        # 长期项目（每个独立 git 仓库）
├── work/            # 当前工作区（根目录只放 AGENTS/CONTEXT/MAP 与项目目录）
├── scripts/         # 按主题分组的脚本（如 chrome-cdp/、windows-ui/）
├── tools/           # 独立工具集合
├── installers/      # 安装包，下载后立即归档
├── archive/         # 已完成/只读，不再改动
└── data/            # 全局只读数据集（可选）

~/work/<project>/
├── README.md        # 一眼看懂：是什么/怎么跑/接口
├── AGENTS.md        # 模块地图、约定、验证命令
├── src/ 或 app/     # 代码
├── tests/
├── docs/            # 长文档
├── data/            # 数据资源（只读）
├── outputs/         # 生成产物（gitignore）
└── scratch/         # 临时/一次性质（gitignore，定期清理）
```

## 创建文件决策表（快速查）

| 要创建的是什么 | 放哪里 | 命名示例 |
|---|---|---|
| 新代码/项目 | `~/work/<project>/src` | `auth-service.ts` |
| 一次性脚本 | `~/scripts/<topic>/` | `chrome-cdp/inspect.js` |
| 数据/查询结果 | `<project>/data/` | `cf_problems.json` |
| 报告/文档 | `<project>/docs/` 或 `~/work/docs/` | `2026-09-06-file-management.md` |
| 临时实验/草稿 | `<project>/scratch/` 或 `/tmp/` | `exp-2026-09-06-ab-test/` |
| 规范/标准 | 技能库或 `~/work/standards/` | `ai-behavior-standards` |
| 已完成/归档 | `~/archive/` | `project-name-2026-09-06/` |

## AI 自检清单（每次涉及文件前过一遍）

- [ ] 路径属于上述标准目录之一，不在根目录裸堆？
- [ ] 文件名包含“项目/主题 + 日期（如需）”且无 `final/副本/未命名`？
- [ ] 数据/产物/文档/代码四类是否分开？
- [ ] 是否先查重，避免同名散落版本？
- [ ] 是否碰了用户已有文件？若有，是否已备份并确认？
- [ ] 临时文件是否只进 `scratch/` 且会话结束清理？
- [ ] 是否更新了模块入口（README/AGENTS/CONTEXT/HANDOFF）？

## 边界 / 反模式

| 反模式 | 正确处理 |
|---|---|
| 写了一大堆细则规范 | 只留可执行硬底线 + 检查表；细节进 `CONSENSUS.md` |
| 把整理当“移动所有文件” | 先备份、分批、可回滚；没把握不乱动 |
| 用长 prompt 救结构混乱 | 修目录/命名/接口，别靠提示词 |
| 只给正例不给反例 | 每条规则都要有“什么时候不适用/会翻车” |
| 生成产物留在项目根 | 进 `outputs/` 并 gitignore |
| 每刻都问用户“放哪” | 一次问最高信息增益问题；常规按决策表执行 |

## 简单用户话术

> 我先给你三样东西：**方向**（AI 缺的是可检查规范，不是更多知识）、**方式**（创建前先回答“哪/叫啥/何时清”，按目录骨架与检查表执行）、**边界**（不静默动你已有的文件，不靠长文档救结构）。
>
> 如果哪条和你的直觉冲突，请说“我感觉不对劲”，我会停下来重新核验。
