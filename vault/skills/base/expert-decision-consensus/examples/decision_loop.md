# 九段决策环 · 一页示例

> 目标：展示同一个 `expert-decision-consensus` 如何用于科研、教学、开发三类任务。
> 实际使用时只保留与本任务相关的证据字段；不要为了“完整”而空跑无关阶段。

## 科研：给 VLPC 论文做组会前审查

```text
0 Brief       ：下周组会讲这篇 NOMA-VLPC 论文；交付 10 分钟汇报 + 3 个可被追问的点。
1 Evidence    ：读原文，OpenAlex/Crossref 核验 12 条引用；把方法/实验/局限写进证据表。
2 Panel       ：Ting Yang（架构）、Ping Wang（定位算法）、S. Ma（波形）分别独立点评。
3 Conflict    ：c1：是否需要补与 NOMA-VLC 的公平性对比？c2：公式符号是否要统一？
4 Adjudicate  ：用户裁决：补对比列为风险点，不阻塞汇报；符号统一列为修改项。
5 Plan        ：汇报结构 + 引用核验清单 + 2 个可能被追问的问题与证据位置。
6 Execute     ：子代理 A 抽表格、子代理 B 查公平性文献、子代理 C 整理 PPT 初稿。
7 Verify      ：P1=0；每个数字都能回原文；PPT 中的引用逐条可点开。
8 Log & Distill：回写论文台账；把“组会审查三问”沉淀为 research-module 候选子技能。
```

## 教学：拆一道 DP 题

```text
0 Brief       ：学生卡在“为什么 DP 要倒推”；交付一次能让他自己写出来的引导。
1 Evidence    ：读学生当前代码 + 题目约束；不先给答案。
2 Panel       ：两位竞赛导师独立表态：先暴力 / 先重述不变量。
3 Conflict    ：引导顺序冲突，保留两条分支。
4 Adjudicate  ：用户选择先重述“最后一步依赖什么”。
5 Plan        ：3 个追问，按信息增益排序。
6 Execute     ：逐问推进；只在学生说出关键依赖时进入下一步。
7 Verify      ：学生在不给答案的情况下写出转移方程。
8 Log & Distill：把该追问序列加入 teacher 教学技能候选。
```

## 开发：给模块加缓存

```text
0 Brief       ：给某模块加缓存；不改变公开接口；交付测试 + 代码 + 验证报告。
1 Evidence    ：读现状源码、依赖、现有测试。
2 Panel       ：架构/性能/安全专家独立表态。
3 Conflict    ：缓存放 API 层 vs 数据层；是否用 TTL。
4 Adjudicate  ：用户选 API 层 + TTL；数据层保留为后续分支。
5 Plan        ：接口不变；先写会失败的测试。
6 Execute     ：子代理实现；重叠文件串行；不碰 git 状态。
7 Verify      ：测试先红后绿；破坏缓存键验证会红；redteam 通过。
8 Log & Distill：回写模块地图与决策日志；把“加缓存”流程固化为 dev 技能候选。
```

## 简单验收口诀

> 每个阶段都问一句：**“这一步有没有可检查的证据？没有就回上一步。”**
> 每个结论都问一句：**“这条能不能点回来源？不能就标 unknown，不硬凑。”**
