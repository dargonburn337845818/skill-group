# dev-design-aesthetics · 设计美学/风格库（已挂载）

> 状态：已填充（挂载 `vault/skills/distillation/ui-aesthetics-design/`）。本挂载点不重复已蒸馏内容，只做 dev 调用与剩余缺口追踪。

## 触发条件

- 用户要求生成/审查网页组件、仪表盘、表单的视觉美感与可用性。
- 需要做配色、字体、间距、层级、控件、焦点态、动效检查。
- 需要判断某个界面属于哪种风格分支（现代/极简/数据密集/品牌强风格）。

## 核心动作

1. **引用**：直接调用已填充的 `ui-aesthetics-design`，按其“定场景 → 检查清单 → 收口”三步执行。
2. **补缺口**：只蒸馏现有 skill 未覆盖的风格库缺口（如特定产品风格、数据密集规范、暗色模式进阶）。
3. **验收**：用 `skill-verification-consensus` 检查新增规则是否有来源、有反例、是否被标为“风格分支”而非普适规则。

## 边界 / 反例

- 不重新蒸馏 `ui-aesthetics-design` 已覆盖的内容，避免重复与漂移。
- 不负责品牌 VI/Logo 设计；那是独立任务。
- 不把单一风格（零圆角/无阴影/单色等）当普适标准，必须标为风格分支并降权。
- 数据密集界面/品牌强风格需要叠加专项边界，不能直接套极简美学。

### R36-1 表格按四任务裁剪：先支持找、比、改、做
- **触发**：遇到大型数据表格/工作台表格；用户抱怨“表太乱”“找不到行”“列离得太远”。
- **动作**：先问这个表格支持哪几个核心任务——**找记录、比较数据、查看/编辑/新增单行、对记录操作**；默认第一列用人类可读记录标识（名称/编号），不要放自动生成的“mystery meat” ID；默认列顺序按用户重要性排列、相关列相邻；表大于一屏时**冻结表头和首列**；用轻边框 + 斑马纹/hover 高亮帮助眼睛保持在行上；隐藏/重排列要低门槛且**清楚显示当前隐藏状态**。
- **反例**：第一列是 UUID、第 1 列与第 20 列是唯一相关字段、无冻结头、滚动后不知道在看哪一行。
- **通过示例**：表格第一列是客户名，金额列紧邻客户名；滚动时表头冻结，hover 整行高亮；列隐藏菜单显示“已隐藏 15 列”。
- **边界**：产品对比表/电商参数表另有任务模式；小表格不需要冻结；编辑单行时避免用遮挡相邻记录的模态，除非宽表确实无法就地编辑。
- **来源**：NN/g `Data Tables: Four Major User Tasks`。

### R36-2 仪表盘用“可前注意”编码：长度/二维位置优先，面积只作定性
- **触发**：设计或审查监控/分析仪表盘；用户要看“一眼知道哪里异常、变化多大”。
- **动作**：关键量化关系优先用**长度（柱/条）与二维位置（折线/散点）**表达，因为人能快速且较准确地比较长度与位置；颜色、形状、空间邻近用于**分组/类别**，且颜色只作辅助、与形状/分组组合使用；先判断是**操作型仪表盘**（持续更新、时间敏感、立即行动）还是**分析型仪表盘**（供调查/研究），两者的告警强度、刷新与动效都应不同。
- **反例**：全屏饼图/树图/面积图表达销售金额，观众能看出“大/小”却无法准确判断“大多少”；类别只靠不同颜色，色盲用户无法分组。
- **通过示例**：KPI 区用柱状图显示“本周 vs 上周”，异常月用长度突出；类别用“形状 + 颜色 + 邻近”三重编码。
- **边界**：探索性分析需要比较多个维度时，不要硬归一个“重点”；面积图可用于定性占比/层级关系，但不能用于精确定量。
- **来源**：NN/g `Dashboards: Making Charts and Graphs Easier to Understand`。

### R36-3 暗色模式先定优先级，再实现：镜像系统、降饱和、检查“看不见的分隔”
- **触发**：用户要在已有浅色产品上补暗色；暗色下出现“字看不清、分割线消失、悬浮按钮找不到”。
- **动作**：用优先级清单决定投入——**长会话（阅读/监控）、高频使用、低光环境、少媒体**这些条件命中越多越值得做；默认**镜像操作系统暗色设置**，不要强迫用户二次开启；文字用“同一色相 + 不同透明度”适配不同暗背景，而不是每处换一种色；高饱和色在暗底上视觉发糊——即便对比度勉强 4.5:1 也应降饱和或换浅色调；检查**细灰分割线、卡片边界、悬浮组件、overlay/弹窗遮盖**在暗色下是否仍然可见；邮件/内嵌网页要单独检查，不能只测 App。
- **反例**：App 已暗色，内嵌网页仍是白底；卡片在暗色下只剩 1px 深灰边，几乎无法区分；主蓝色高亮在暗灰底上 4.59:1，但仍像发光糊边。
- **通过示例**：跟随系统设置；正文用一个浅灰 token 配 87%/60% 透明度；卡片用比背景亮一档的面板色而非只靠边框；所有弹窗/scrim 在暗色下仍能看出层级。
- **边界**：暗色不是必须项；不要为了“暗色更现代”牺牲基础可用性；纯装饰可保留品牌饱和度，但状态/文本/交互控件必须过对比。
- **来源**：NN/g `Dark Mode: How Users Think About It and Issues to Avoid`；NN/g `Dark Mode vs. Light Mode: Which Is Better?`；Apple HIG `Dark Mode`（官方入口，正文 JS 渲染，经 NN/g 研究交叉核验）。

### R36-4 暗色层级用“亮度差”造，扫描码/图片不可被反色
- **触发**：暗色模式审查；QR/条形码、图片、logo 在暗色下失效。
- **动作**：暗色下用**微亮面板色、透明度、轻描边**制造 component 层级，不要只靠阴影/细线；浮动按钮/悬浮卡要在暗色下同样“浮起来”；**不要把 QR/条形码/验证码反色**，扫描设备通常要求深前景浅背景，应保持固定浅底或使用不随主题变的 PNG；logo/插画用透明底并检查暗色下的可见性；图片/照片在深浅色下不应改变可读性。
- **反例**：暗色下 QR 被反色导致扫码器失效；浮动按钮在暗色下与背景融为一体；深色底上 1px 灰线全部消失，页面结构散架。
- **通过示例**：卡片使用 `#1E1E1E` 面板色放在 `#121212` 背景上 + 1px 浅边；QR 始终白底黑码；浮层用 `background` 差异而非阴影。
- **边界**：纯品牌艺术字可以反色；但承载功能/识别/扫描的资产必须保持可读可扫。
- **来源**：NN/g `Dark Mode: How Users Think About It and Issues to Avoid`；Apple HIG `Dark Mode`。

### R36-5 动效先回答“帮用户知道什么”，再谈时长；一次只留一个焦点
- **触发**：页面/工作台动效多；加载页连续闪多个动画；用户觉得“晃眼、找不到重点”。
- **动作**：给每个动效标一个目的：**反馈（操作被识别）、状态变化（模式/数据切换）、空间隐喻（层级/方向）、强化 signifier**；不服务于这些目的的动效删掉；动效应**短、轻、不抢焦点**；同屏**不要同时运行多个互抢注意力的动画**（logo 飞 + 数字滚动 + progress + 骨架屏微光同时上，等于互相抵消）；为同类交互定义统一 motion language（同方向、同 ease、同档时长），跨页保持一致。
- **反例**：搜索加载时 chipmunk + 数字爬升 + 占位符 + progress + 结果重排序五路动画同时发生，注意被竞争稀释；每个按钮 hover 方向都不一样。
- **通过示例**：拖拽表格列时先预览新顺序再松手确认；新增列表项只做一个轻微淡入/位移；所有面板进入都用同一从右滑入 + ease-out。
- **边界**：品牌展示/营销页可更长更多，但阅读/工作台/表单应克制；已有 `prefers-reduced-motion` 的响应不可省；本轮管“动机与一致性”，时长上限仍按 R35-5（100–400ms 为主）。
- **来源**：NN/g `The Role of Animation and Motion in UX`；Apple HIG `Motion`；Material Design 3 `Motion overview`（官方入口，正文 JS 渲染，经 NN/g 交叉核验）。

### R36-6 品牌层与功能层分离：品牌=可视 + 语气 + 行为
- **触发**：需要“有品牌感”又不想毁掉数据/表单可用性；品牌方要求全站用品牌色、大字、专属插画。
- **动作**：把品牌拆成三通道——**可视（logo/字标/主色/字体/图片风格）、语气（文案/语调）、行为（响应性、标签清晰度、一致性）**；实现时做两层：**品牌层**（少量出现：logo、hero、空状态、典型插画、关键标题）与**功能层**（正文、表格、按钮、状态、数据编码按通用规则）；品牌主色拿来做按钮背景/链接时仍按 4.5:1/3:1 检查；品牌风格指南必须写“可访问色组合”而不仅是色号；不要为了品牌一致性牺牲标签、可发现性与可预期行为——交互行为本身会改变用户对品牌的感知。
- **反例**：整个管理后台都是品牌大字 + 品牌色块，但按钮对比不足、表格扫描困难；或只改 logo 和颜色，却让加载、错误、反馈行为与竞品无差别。
- **通过示例**：数据后台保持中性功能层，只在导航 logo、欢迎页和空状态使用插画与品牌字体；所有主 CTA 用品牌色但通过对比；品牌“专业/可靠”通过清晰标签与可预期反馈表达。
- **边界**：纯品牌展示页可整页强风格；承载任务的界面必须保留功能底线；品牌风格仍属风格分支，不作通用规则。
- **来源**：NN/g `Brand Is Experience in the Digital Age`；NN/g `The Impact of Interaction Design on Brand Perception`；NN/g `Design Systems vs. Style Guides`。

### R36-7 视觉一致性靠“系统/指南”父子结构，不要靠复制粘贴
- **触发**：多个团队/页面出现同一概念的多个近似变体；新页面“越来越不像旧页面”；样式 review 靠人肉记。
- **动作**：把**设计系统（父）**与**风格指南（子）**分开：设计系统管“可复用组件 + 模式 + 标准”，风格指南管“视觉/内容/品牌的窄切片”；新增界面先查系统里有没有组件/token，复用而不是复制；做**变体审计**：数一遍同类圆角/阴影/主色/字号在代码中的实际值，出现 3 个以上近似变体就合并成 token；品牌风格指南至少覆盖：主/次色与可访问组合、字体族与用途、logo 变体/间距、图片/插画风格；跨团队一致性的验收不是“长得一样”，而是**同一交互用同一套 token/组件**，语境差异允许。
- **反例**：两个团队各自实现同一个下拉，出现 5 种蓝、3 种圆角；品牌文档只有 logo 和色号，没写按钮对比度与图片规则；新页面直接复制旧页面 CSS，后续无法统一修 bug。
- **通过示例**：组件从设计系统取，品牌指南只覆盖“品牌层”用法；CSS 中圆角只有 4/8/12/16 四个 token；任何新增变体先走“能否归并到现有 token”评审。
- **边界**：不能为了极端一致冻结所有探索；营销组件可允许一次性风格，但功能组件与交互模式必须回系统；没有系统时先建立最小 token 集，而不是先建几十页规范。
- **来源**：NN/g `Design Systems vs. Style Guides`。
