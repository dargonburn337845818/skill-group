# 提示词模板骨架（prompt_template）

> 用途：把一次任务/讨论转成可直接复制使用的 prompt。
> 调用方：teacher / research / distill / 任何需要“让模型/专家做某事”的场景。
> 使用前先填 `【】` 中的占位；无法确认的内容保留 `[待补]`，不要编造。

## 模板 A：单任务执行类

```text
【角色】你是【角色，如：代码审查助手 / 论文阅读助手】。
【任务】请完成：【一句话目标】。
【背景】
- 领域：【domain】
- 已知事实：【只放调用方确认过的内容；无来源写 [待补]】
- 约束：【不要使用：... / 必须包含：...】
【输出格式】
1. 先用一句话复述任务，确认理解一致。
2. 给出执行步骤或结果。
3. 不确定处明确写“未知”，不要猜。
【边界】
- 不得编造数据、引用、专家原话。
- 若信息不足，先列出需要调用方回答的问题，再输出。
```

## 模板 B：多专家讨论类（teacher / research）

```text
【背景】我们正在讨论：【topic】。目标：【purpose】。
【专家团】
- expert_id: 【如 tourist】
  - 立场/方法：【一句话；公开来源风格参考须注明 sourceRefs】
  - 擅长：...
  - 不擅长：...
- expert_id: 【如 jiangly】
  - 立场/方法：...
【任务】请每位专家独立表态，不要互相串词。
【输出格式】
1. 每位专家一条结论，必须标注 expert_id 与 expert_name。
2. 若有冲突，单独列出：
   - claim_a: 【专家/来源】
   - claim_b: 【专家/来源】
   - 分歧点：...
3. 最后不自动裁决；把裁决权交给主持人/用户。
【边界】
- 不得虚构专家原话；风格参考必须写“风格推断”。
- 没有源头的“共识”不能写成专家结论，只能写 [待补]。
```

## 模板 C：拆题追问流（teacher 场景）

```text
【对象】学生/学习者。
【当前状态】学生说：【如：只会暴力，不知道怎么优化】。
【目标】通过一次一个问题引导，不直接给出答案。
【规则】
1. 一次只问一个问题，必须能回答“是/否/不确定”。
2. 问题不得包含算法名或答案。
3. 根据上一个回答选择下一个问题；优先问能排除最多可能性的问题。
4. 连续追问直到学生能自己说出方向；若学生说“我感觉不对劲”，停下来重新校准。
【输出】只输出下一个问题，不超过三行。
```

## 使用说明

- 复制后替换占位符；空白处必须向调用方提问，而不是自行编造。
- 多专家模板保留 `expert_id/expert_name/sourceRefs`，不得抹平分歧。
- 本文是骨架，不是唯一格式；用户可覆写结构。
