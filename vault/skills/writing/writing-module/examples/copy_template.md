# 文案模板骨架（copy_template）

> 用途：README / PR 描述 / 公告 / PPT 文案 / 发布说明。
> 调用方：dev 模块为主，也可用于 teacher/research 的对外/内部说明。
> 核心：具体动作 + 短句 + 人味；不夸大、不编数据。

## 模板 A：发布说明 / 更新日志

```text
# 版本标题：【vX.Y.Z · 一句话变化】

## 新增
- 【功能：用户能做什么，动作开头】
  - 示例：`/inject <path>` 可以直接加载本地插件，不用重启。
- 【功能 2】

## 修复
- 【问题：之前怎样，现在怎样】
  - 示例：修复路由表残留导致重复加载的问题。

## 变化/注意
- 【如果有破坏性变化，必须写清升级方式】
  - 示例：配置字段 `old` 改为 `new`，请迁移后再升级。

## 待补
- [ ] 截图/数据：【截图占位】
- [ ] 链接：【文档/仓库地址】
```

## 模板 B：README 开头（技术项目）

````text
# 【项目名】

用一句话说清：**做什么**，给谁用，解决什么问题。

## 快速开始
```bash
# 安装/克隆命令
# 第一个可运行命令
```

## 这是什么
- 【为什么值得用 / 与替代方案的关键差异】
- 【边界：不做什么】

## 文档
- 【链接到详细文档】

## 参与
- 【如何提 issue / PR】
````

## 模板 C：PPT 单页文案

```text
【页标题：一句话主张，不超过 12 字】
- 支撑句 1：【可验证的事实/数字/动作】
- 支撑句 2：【对比或代价】
- 支撑句 3：【下一步/提问】
```

## 模板 D：去 AI 味改写对照

```text
原文：【“赋能业务闭环”“综上所述”等 AI 腔】
问题：【空泛词 / 无主语 / 无具体动作】
改写：【短句 + 人称 + 具体动作 + 可验证结果】
```

## 使用说明

- 每个 `【】` 都必须有依据；没有事实就写 `[待补]`。
- 不写“行业领先”“绝对最优”；用数据或留白。
- 用户说“要正式”/“要轻松”时，只调整语气，不改变事实。
