# 演讲 / 口播 / 视频脚本（speech-writing）

> 属于 `writing-module` 子技能。
> 负责表达：把素材组织成“用来听/用来读出来”的文本，而不是“用来看的书面文档”。
> 不负责：核实事实与数据、判断观点正确性、决定演讲者实际如何表演。

## 触发条件

- 用户要写演讲稿、口播稿、视频脚本、旁白/配音稿、PPT 演讲者备注/口述稿。
- 需要把一个已有文档改写成“照读不拗口、计时不超过”的口语版。
- 需要判断一篇口播稿/演讲的结构、节奏、时长是否合格。
- dev/teacher/research/distill 需要把说明、讲解、汇报变成可讲的文本。

## 输入契约（speech 版 TextRequest）

```json
{
  "topic": "核心主题",
  "medium": "speech | oral-narration | video-script | ppt-talk",
  "audience": "学生 | 客户 | 评审 | 大众 | 同行 | 领导",
  "duration": "90秒 | 5分钟 | 20分钟 | 每页40秒",
  "purpose": "说服 | 解释 | 带货 | 汇报 | 教学 | 破冰",
  "tone": "轻松 | 正式 | 激昂 | 克制 | 鼓励",
  "constraints": ["不要念PPT", "去AI味", "必须带来源", "不许超过3分钟"],
  "references": ["素材/数据/引用链接"],
  "speaker": "可选：谁在讲，职业/身份/口吻"
}
```

- `medium` 缺失时先问，不要默认成书面稿。
- 没有素材时输出 `questions` / `placeholders`，不编造数据、案例、引语。

```json
  "questions": ["必须由用户回答的关键问题"],

  "notes": "时长估算、结构说明、事实核验提醒"
}
```

## 核心动作

### 1. 先定形态与约束，再动笔

- **触发**：任何口播/演讲/视频脚本任务开始前。
- **动作**：确认 `medium / audience / duration / purpose / tone`；为每个产出定一个“听众听完后要带走的一句话”。
- **边界**：没有时长、没有受众就写，容易写出“书面文档”而不是“可讲文本”。

### 2. 搭结构骨架

- **演讲**：`引言（吸引注意 → 点题 → preview）→ 主体（2–5 个观点）→ 结尾（回顾 + 收束/行动）`。
- **视频脚本（营销/转化型）**：`Hook（前 3–5 秒）→ Problem → Solution → Proof → CTA（只有一个明确动作）`。
- **说服型**：可用 Monroe's Motivated Sequence：`attention → need → satisfaction → visualization → action`。
- **PPT 讲稿**：`封面 → 背景/问题 → 核心内容（1–4 页）→ 方法 → 总结 → 收尾`；每页只讲一件事。
- **动作**：主体观点用“平行措辞 + 过渡句 + 内部小结”让听众能跟上；观点超过 5 个时砍掉，不要硬塞。
- **边界**：结构是起点不是枷锁；但“没有结构”通常等于听众抓不住。

### 3. 写成“说出来”的话

- 短句优先；多用第一/第二人称和缩写（“我们”“你”“别”“咱们”）；少用“综上所述”“其次”“此外”等书面标记。
- 每一句都读一遍：读起来拗口、需要换气、像在念文档，就改写。
- 用具体细节和故事：一个具体画面（“白大褂”“白色领带”）比十个抽象形容更让人记住；故事/例子不超过 1 分钟，给细节后立即回到观点。
- 保持一个核心信息：任何一句不影响这个信息的，删。
- **边界**：口语化不等于口语垃圾；短句可以有，但逻辑仍要清楚；专业术语首次出现要解释。

### 4. 控制节奏与时长

- 英文口语规划常用 **130–150 wpm**；5 分钟约 650–750 词（WordCount 指南）。**其他语言/方言必须先实测**，不要照搬英文数字。
- 用“朗读计时”校准，不做默读估算；紧张会使实际语速比排练快，所以写到中低档并留缓冲。
- 超时处理：**砍整块观点/段落，不要压缩句子**；视频脚本把可删内容放在中间，Hook 和 CTA 不砍。
- 宁可短 30 秒，不要拖尾；结尾被匆忙讲掉是最吃亏的。
- **边界**：时长控制是“口语文本”的硬约束，但不能用牺牲必要事实或结论来凑时间。

### 5. 视频脚本专用

- 开头 3–5 秒必须抓住注意力：用一句反常识/一个问题/一个具体画面，不要慢热铺垫。
- 一镜/一段只服务一个信息；能“看到”的句子优先（写场景/画面/动作提示），不能画面化的抽象句要简化。
- 证明（proof）要直接支持前面的主张：数字、案例、截图都行，但必须与声称一致；“为放而放”的证明不如没有。
- CTA 只给一个动作，写具体（“点这里预约” vs “了解更多”）。
- 交付格式：`[镜头/画面] + [口播词] + [时长] + [字幕/提示]`，方便剪辑与后期。
- **边界**：视频脚本不是录音稿；看不见的内容要标出来，避免剪辑时才发现。

### 6. PPT 讲稿/备注

- 每页标题写**结论/主张**，不是名词；每页只讲一件事；列表不超过 5 条。
- 每页可配 100–250 字的照读口述稿，或更短的备注（本地 ai-ppt-skill 约定）。
- 屏幕只放关键词/图/数字，完整句子交给口述稿；讲稿里可以写“[指图]”“[停顿]”等舞台提示。
- 页面之间的过渡语要写出来，避免“下一页”干跳。
- **边界**：PPT 讲稿不是要你把 PPT 原文念一遍；也不是替用户决定视觉设计（见 dev-art-ppt）。

### 7. 事实与边界

- **不编造**：数据、案例、引语、观众反应都必须来自 `references` 或标 `[后续]`；不写“众所周知”“经调查”等无出处表述。
- **不代替事实核验**：本子技能只负责表达与结构；引用是否真实、数字是否最新，由调用方/用户核验。
- **不夸大承诺**：不写“一定成功”“行业第一”等无法验证的承诺；讲优缺点时要保留边界。
- **注意开场方式**：冷笑话、夸张道具、滥用的反问可能损失可信度；选择与场合/身份匹配的开场。
- **不把PPT当稿子**：口播稿是可读出来的句子，PPT 是视觉提示，不要互相替代。

## 交付前检查清单

- [ ] 已明确 medium / audience / duration / purpose
- [ ] 有引言/主体/结尾（或视频 5 段结构、PPT 每页一个主张）
- [ ] 只保留一个核心信息，观点 ≤5 个
- [ ] 全文朗读一遍：是否拗口、是否像书面稿
- [ ] 按目标时长估算字数/分钟，超时已砍整块而不是压句子
- [ ] 数据/案例/引用均有来源或 `[后续]`
- [ ] 视频脚本有 Hook、单一 CTA、每段可画面化
- [ ] PPT 讲稿已配到页、有过渡、有备注/舞台提示
- [ ] 已标注哪些内容必须由用户/专家核验

## 反例与边界

| 不要 | 改为 |
|---|---|
| 把报告原文逐字读出来 | 按“一句话结论 → 2–3 个支撑 → 一句收束”重写成口语 |
| 开头先“大家好，我是……”再铺垫 30 秒 | 前 3–5 秒先给反常识/问题/具体画面，身份后置 |
| 一个视频塞 5 个卖点 | 一个视频只打一个核心信息，其余放后续内容 |
| “效果显著提升”无数字 | “相比上周，这个指标从 X 到 Y；数据来源：[后续]” |
| 每页 PPT 写满段落 | 每页一个主张 + 口述稿承担细节 |
| 超时后把句子压短 | 砍掉一个整点，保住 Hook/CTA/结尾 |
| “敬请期待”“了解更多” | “现在点击预约 15 分钟演示” |
| 讲稿里出现没核实的“研究表明” | 改为 `[来源后续]`，或引用真实可溯源来源 |

## 示例模板（可替换）

### 60 秒视频脚本（转化型）

```text
【Hook 0-5s】“你 3 秒没看懂，就不会看完。”——具体痛点/反常识。
【Problem 5-15s】描述观众正在经历的、具体的一个问题（不是泛泛的“效率低”）。
【Solution 15-35s】一句话说清“我们做什么”，讲好处不讲功能表。
【Proof 35-50s】一个数字/一个截图/一句用户结果（带来源或 [后续]）。
【CTA 50-60s】一个明确动作：“点击这里/评论 1，我发你模板。”
```

### 5 分钟演讲骨架

```text
【开场 30s】故事/具体画面 → 一句话主题。
【正文 3×70s】三个观点，每点：主张 → 一个具体例证 → 回到主题。
【过渡】每点之间一句“这就引出了/但问题是……”。
【结尾 30s】回顾 three points → 一句可带走的行动/画面。
【时长】按 130-150 wpm 预算 650-750 词；朗读计时后按整块删减。
```

## 2026 深度补强（Round 34）

> 新增规则，针对前文未覆盖的“目的分类、听众分析、注意力曲线、说服四门槛、变速、短视频脚本、配音导演注记、照读稿改造”。每条注明来源以便追溯。

### 1. 先写“五个目的之一 + 一句话 purpose statement”

- **动作**：动笔前把目的归入五类之一：**inform / persuade / entertain / inspire / motivate**。inspire 是情绪/内在（“想通一件事”），motivate 是外化/行动（“马上去做一件事”），不要混用。
- **动作**：把目标压成一句话：`这篇讲完，我要听众 [知道/相信/笑/感到/去做] ______。` 然后写正文；**开场最后写**——写完正文后往往才找到最自然的钩子。
- **反例**：没有 purpose 就写“主题内容”，听众听完不知道为何要听；把“激励人心”写成“立刻购买”，属于目的错位。
- 来源：Toastmasters, “How to Write a Speech With Purpose”。

### 2. 听众分析三段式：人口统计 / 心理画像 / 情境

- **动作**：写作前至少过一遍：**他们期望什么？已知多少？态度如何（-3 到 +3）？自愿来还是被迫来？现场多大、几点、有无麦克风/噪音？**
- **动作**：用分析找“到达目的的最佳手段”，而不是改目的或讨好听众。**不要刻板印象化**；强烈反对的人通常一场讲不翻，主攻中间派/未决定/轻度反对者（target audience）。
- **示例**：听众已支持建公园、只担心安全 → 把整段时间用来讲安全数据，而不是再夸一遍公园好处。
- **反例**：明知听众完全反对仍在开头抛结论；或反过来把所有内容都调成“听众爱听”而丢掉自己的立场。
- 来源：Pitt Audience Adaptation；Lumen “Three Types of Audience Analysis”；Lumen “Using Your Audience Analysis”。

### 3. 注意力是 U 形曲线：把重注下在开头和结尾

- **动作**：开头 30 秒用 INTRO 模型：**Interest（凭什么听你）→ Needs（对我有什么好处）→ Timing（讲多久）→ Routemap（讲哪几点）→ Objectives（结束时要我做什么）**。
- **动作**：中段注意力最低，每 2–3 分钟换一次节奏（提问、画面、短故事、换语气）；结尾提前背熟，并选一种 closing：**quotation close / bookend close（回到开头）/ open question 或 CTA**。
- **反例**：开场说“抱歉我有点紧张”“我是最后一场，大家坚持一下”“我们时间紧我快点讲”——这些会让听众把注意力放到你的紧张/时间上。
- 来源：VirtualSpeech, “How to Write a Speech to Engage your Audience”。

### 4. 说服先判“卡在第几道门”：不听 → 不懂 → 不同意 → 不行动

- **动作**：写说服稿前判断：听众是**不关心**、**听不懂**、**有保留**，还是**知道但不动**。每一层用不同打法：不关心→讲直接利害；听不懂→先解释术语；有保留→主动说出并反驳；不动→给具体、低门槛的第一步。
- **动作**：对保留意见用“two-tailed”处理：先承认“有人会担心……”，再给证据反驳，不要把反对者说成“你错了”。同时让听众看到 **改变收益 > 改变成本**（“What’s in it for me?”）。
- **反例**：只列赞成理由、忽略脑中正在反驳的“yeah-but”；想用一场演讲把 -3 听众拉到 +3；证明恐惧时只说“很可怕”而不证明“与你有关、解决方案可用”。
- 来源：Boise State, “11.3 Persuasive Speaking”；Pitt Audience Adaptation。

### 5. 时长与语速按场景变速，不只用一档

- **普通演示/口播**：120–160 wpm；**说服、复杂、高风险内容**：降到 100–120 wpm，给听众处理时间；**视频长视频**可到 150–200 wpm；**Shorts** 整支控制在 100–200 词。
- **换算参考**：3 分钟 ≈ 390–450 词；5 分钟 ≈ 650–750 词。
- **动作**：拿到稿子先标“哪里必须慢”：论证、数字、新术语、转折处；不要通篇匀速。PPT 页面上只放一个数据点/视觉隐喻，减少读屏冲动，才能稳住语速。
- **反例**：用 160 wpm 念政策/金融论证，听众还没吸收就下一页；或短视频硬塞长视频口播词。
- 来源：24Slides Speech Timing Guide；Clipchamp YouTube Script Guide。

### 6. 短视频与长视频脚本分开写

- **Shorts（≤3 分钟）**：hook → main content → CTA；**每个新想法/每句最好换一个画面**；**最后一句写成循环 hook**（让循环播放时重新钩住观众）。
- **长视频**：hook 可选 cold open（开场即中间行动）、facts/stats、surprise & twist；随后用一句/一小段做 channel branding + 本集 topic tease；主体用提纲而非逐字稿（教育/纪录片可逐字），结尾总结 + 单一 CTA。
- **反例**：Shorts 末尾“感谢观看，我们下次见”（循环时无注意力）；长视频开头 60 秒自我介绍才进正题。
- 来源：Clipchamp, “How to write a script for a YouTube video”。

### 7. 配音/口播稿要写“导演注记”，不只是句子

- **动作**：给配音/AI TTS 写明 `[pause weak/medium/strong]`、`[强调]`、`[放慢]`，短句 + 主动语态；把“你在对谁说话”具体化为一个虚构 persona（年龄/处境/想知道什么），边写边以这个 persona 的口吻读出来。
- **动作**：把核心信息压缩成一句话，每轮改稿后回去对照；像编辑一样把自己当外人删填充词/冗余句。
- **示例**：`要进步，[pause x-weak] 先学会这些技能：沟通、[pause medium] 适应力、[pause strong] 团队协作。`（比纯书面标点的停顿更可控）
- **反例**：把长句、被动语态、靠配音演员“救场”的文本直接交给 TTS；写作时不标停顿，剪辑时才发现句间没有呼吸。
- 来源：Murf AI, “How to write a voiceover script”。

### 8. 必须照读时：把稿子改造成“可读提示”，并执行 See-Stop-Say

- **动作**：用大号无衬线字体（Arial/Verdana，20 号左右）、双倍行距、短行；用自己惯用的记号标重音/停顿/放缓；把稿子放讲台，讲台稍偏一侧，避免挡住脸和视线。
- **动作**：用 **See-Stop-Say**：看一个完整短语 → 停下看观众 → 说出来 → 回到下一句。读完一个句子至少抬一次头。
- **反例**：小五号整段黑字低头念到底；以为“自己写的稿子读起来没问题”而不真正大声排练。
- 来源：Write Out Loud, “How to read a speech effectively”；Write Out Loud, “Vocal aspects of speech delivery”。
