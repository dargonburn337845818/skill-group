# 算法竞赛教师共识 · 熵减盘问

> 不背模板，练拆题。
> 一次只问一个高信息增益的问题，把候选算法的不确定性一步步降下来。

## 这个技能是什么

这是“教师共识文本”，同时也是未来静态软件的数据源头。它做三件事：

1. **定性共识**：顶尖选手普遍认可、可教、可模仿的解题思维原语。
2. **提问协议**：如何用 grill-me 式盘问，逐步降低学生对算法空间的不确定性。
3. **可编译知识**：每个思维原语都能转成特征问题、条件概率、方向权重，最终进入 `P(特征 | 算法)` 矩阵和熵减引擎。

## 何时使用

- 学生拿到一道题，需要“被引导”而不是“被给答案”时。
- 需要设计拆题问题流、校准信息增益时。
- 需要把一篇题解 / 一段访谈 / 一个提交记录蒸馏成可计算知识时。

## 核心信条

1. **先暴力，后优化。** 写不出暴力，说明还没理解问题。
2. **规模决定复杂度。** 看到 `n ≤ 20`、`n ≤ 5000`、`n ≥ 1e5` 的瞬间，先排除一批算法。
3. **找一个“不会变”的东西。** 高手不是在堆操作，而是在找不变量、单调性、势能、重复结构。
4. **不直接找最优，先“问”系统。** 很多最优化都能转成判定，再利用单调性二分。
5. **一次问一个问题。** 问题流不是四步卡片，是按信息增益动态选出的下一步。
6. **人类可以接管。** “我感觉不对劲”是合法操作，机器的概率模型不能否决人的直觉。

## 四大方向总纲

| 方向 | 一句话本质 | 典型思维原语 |
|---|---|---|
| 编码压缩 | 重复信息提前存好，把慢查询变快查询 | 前缀、预处理、状态压缩、索引 |
| 传播松弛 | 信息沿依赖关系一层层推，前驱替后继铺路 | DP、递推、拓扑序、滑动窗口传递 |
| 剪枝决策 | 利用单调性、可行性、永不优，一次排除大批候选 | 二分答案、单调栈、凸包、决策单调 |
| 变换域映射 | 换坐标系、差分、对偶、重表述，让纠缠变简单 | 区间→点、图→矩阵、原问题→对偶 |

## 教师提问协议（grill-me 式）

每一步只问一个当前信息增益最大的问题。

### 状态机

```text
baseline（确认暴力） → question（动态提问） → finished（四大方向） → direction（深度启发）
```

### 提问规则

1. 先确认“你已经先想了一个暴力/模拟方案吗？”
   - 答“否”或“不确定”：不进入问题流，请先写暴力。
2. 从已定义的 feature 池中选 `argmax IG(feature)` 的问。
3. 问题必须是可回答的是/否/不确定，不能含算法名。
4. 答“不确定”按弱证据更新，权重只降一半。
5. 连续问，直到：
   - 候选池熵低于阈值；
   - 最大信息增益低于阈值；
   - 或用户说“我感觉不对劲”且当前熵已经足够低。

### 分支诊断

当用户给出一个“低概率答案”时，教师不应直接否定，而应诊断：

- 是学生读题漏了信息？
- 是特征问题本身有歧义？
- 是学生的直觉指向一个冷门但正确的方向？
- 是模型矩阵的先验错了？

## 思维原语（Thinking Primitive）

所有蒸馏结果统一为以下结构。这是本技能的原子单位：

```json
{
  "id": "monotone-ask",
  "name": "单调性审问",
  "layer": "consensus",
  "experts": ["tourist", "jiangly"],
  "source_refs": ["codeforces:xxx", "tco19-interview"],
  "trigger": "求最优值/可行值，且可行性随某个参数单调",
  "action": "先写 check(x)，把最优化变成判定",
  "direction": "剪枝决策",
  "feature_hint": "monotonic",
  "algorithm_hints": ["二分答案", "二分查找"],
  "question_templates": [
    "答案或可行性判定随某个量单调吗？",
    "能把最优化改成判定问题吗？"
  ],
  "counterexample": "判定函数有多个峰/不连续时不能直接二分",
  "confidence": 0.92,
  "agreement": 0.8
}
```

字段含义：

- `layer`：`consensus`（多专家共识）/ `style`（单专家风格）/ `warning`（常见错误）
- `experts`：至少一个署名，防止变成无属性总结
- `source_refs`：必须可追溯，不确定来源就标 `common-lore` 并降权
- `question_templates`：未来软件可动态生成的问题
- `counterexample`：这个原语何时失效——防坑层的关键

## 共识分级

| 层级 | 含义 | 进入概率矩阵的权重 |
|---|---|---|
| `consensus` | 多个独立专家/多份资料重复出现 | 高 |
| `style` | 单一专家的独特偏好 | 低，但保留 |
| `warning` | 针对常见错误的反指示 | 作为约束/排除条件 |
| `common-lore` | 没有直接引用，但圈内普遍认同 | 中等，必须标注 |

不要简单平均不同专家。分歧本身是信息：可以保留为两个分支，而不是抹成一条。

## 反例 / 防坑

- 看到“求最小/最大”就急着二分；必须同时满足单调性。
- 看到“区间查询”就上线段树；可能前缀和、差分、莫队、离线排序更简单。
- 看到“图”就 Dijkstra；可能只是并查集、拓扑序、树形 DP。
- 把“不确定”当“否”处理；不确定是弱证据，不是否定。
- 专家用词是“我一般会”，不要把它变成“必须”。

## 如何用 AI 辅助获取知识（蒸馏循环）

这是本技能最关键的使用方式：**AI 负责读得多、记得快；人负责判断“这是不是真共识”。**

### 循环

```text
1. 选语料
   题解 / 访谈 / 提交记录 / 信息论著作
        ↓
2. AI 提取候选 primitive
   每个 primitive 必须带 source_refs 和原始 quote
        ↓
3. 人工/AI 交叉验证
   同一想法是否在多个独立来源出现？
        ↓
4. 共识分级
   consensus / style / warning / common-lore
        ↓
5. 概率校准
   对 OJ 题目抽样，回答 feature 问题，统计 P(feature | algorithm)
        ↓
6. 回测
   用已知标签的题跑 grill 流程，看 top-k 命中率和提问数
        ↓
7. 更新
   只保留真正降低信息增益、且不误导的 primitive
```

### AI 的使用边界

- **可以做**：从大量文本中提取候选项、翻译、归纳、生成问题模板、抽样标注 OJ 题。
- **不可以做**：编造专家说过的话，把推测写成引用；没有 source 的条目必须降权。
- **必须输出**：每条 primitive 的来源 URL/题号/章节，以及“这是原话还是推断”。

## 输出产物

本技能最终应产出两套东西：

1. `teacher-consensus-SKILL.md`：人/AI 可读的教师文本。

## 信息论落点（详细）

信息论不是装饰，而是这个技能的操作规则来源。

### 熵

候选算法池的熵：

```text
H(P) = -Σ P(i) log2 P(i)
```

- 熵高 = 学生还在迷宫里。
- 熵低 = 候选已经很集中，可以停。
- 停止阈值本质上是一个“信息确定性承诺”：我们愿意在多少不确定性下给方向。

### 互信息 / 信息增益

下一个问题应该选：

```text
argmax_q  I(q; algorithm)
       = argmax_q  H(P) - E[H(P | answer(q))]
```

只有能显著改变候选分布的问题才值得问。  
“听起来深刻但不能区分算法”的问题，即使文笔好也应删除。

### 贝叶斯更新

每个回答都是证据：

```text
P(algorithm | answer) ∝ P(algorithm) · P(answer | algorithm)
```

- 专家文本提供 `P(answer | algorithm)` 的先验形状。
- OJ 提交/题目标签提供统计基础。
- 抽样校准把专家直觉变成可验证数据。

### 最大熵原则

当某个算法或特征在 OJ 统计中样本很少时：

- 不要拍脑袋给 0.99 或 0.01。
- 先给温和的均匀/弱信息先验。
- 只加入有证据支撑的偏移。

### KL 散度与反常检测

```text
KL(学生认知 || 教师模型)
```

用户回答与模型预期差异过大时，触发“我感觉不对劲”或反常提示。  
这不是错误，而是一个信号：可能是题面有歧义、模型先验错了，或者学生看到了更好的路径。

### MDL / 最小描述长度

教师共识的最佳版本不是最长版本，而是：

```text
最短且仍能预测/引导解题的版本
```

- 如果一条原语能被另一条覆盖，合并。
- 如果新增问题不能让“平均提问数下降”，删除。
- 这直接对应软件数据文件的精简原则。

### 信道容量 / 提问预算

学生耐心有限，问题流是有限带宽信道：

```text
max_questions = 信道容量
```

每个问题都要最大化有效信息传输，避免低 IG 问题浪费用户注意力。

### 在蒸馏流程中的具体用途

| 阶段 | 信息论用法 |
|---|---|
| 选语料 | 优先选“能提供新判别信息”的来源，避免重复搬运同一套话 |
| 提取 primitive | 每个 primitive 要能解释成 `I(feature; algorithm) > 0` |
| 交叉验证 | 用贝叶斯权重合并专家，不搞简单投票 |
| 概率校准 | 用 Beta 分布对抽样频率做平滑 |
| 回测 | 看平均信息增益、收敛熵、top-k 命中率，而不只看文笔 |

## 2026 深度补强（Round 35）

> 本轮针对四个缺口补可执行细节：①“信息增益”从公式落成可手算的筛问题动作；②专家分歧如何落盘成条件分支；③训练反馈的最小可执行单元；④概率校准的日志纪律。均不与前文 24 条主题重复，只新增动作与边界。

### R1 区分度预检：先画“答案 × 候选”表，再决定问不问

- **触发**：准备问下一个问题；或某问题“听起来很深刻”但直觉上不能区分算法。
- **动作**：把当前候选写成行、把“是/否/不确定”写成列。若某问题对任意两行给出的答案分布几乎相同（即把它答“是”的行集合与答“否”的行集合没有概率质量差异），则 `IG ≈ 0`，延迟或删除。判断标准不是“难不难”，而是“切不切得开”。
- **示例**：候选为前缀和 / 差分 / 线段树时，“这道题是否突然要求单点修改？”能切分；而“题面是不是英文？”不能切分，应删。
- **用户话术**：“我先不问你难不难，只问：这个问题能把你现在犹豫的两种方向分开吗？不能就不问。”
- **反例**：单纯追求 50/50 对半砍 ≠ 最高信息增益；当先验偏斜时，偏斜分割也可能更优（见 R2）。
- **来源**：Wikipedia C4.5 / Information Gain；Codeforces *Unexpected use of Binary Search*。

### R2 先验偏斜时的“锁定冠军”问题，而不是机械对半砍

- **触发**：当前候选概率已偏斜（某一方向 ≥ 0.6~0.7），且其余方向分散。
- **动作**：用期望熵而不是分支平衡性选问题：
  `IG = H(before) - [P(yes)·H(after_yes) + P(no)·H(after_no)]`。
  若“冠军方向”占 0.7，一个把冠军与次候选切开的偏斜问题，常常比一个把低概率候选之间切开的 50/50 问题更有价值。
- **示例**：冠军是“二分答案”（0.7），次候选是“三分”（0.3）。问“check(x) 是否在阈值一侧持续可行？”比问“答案是否单峰？”更可能直接确认冠军或把它降到次候选。
- **用户话术**：“你现在八成是往 A 方向走。我这一问不是平均分注意力，而是专门验证 A 在不在；如果 A 不在，B 才上台。”
- **反例**：冠军概率 > 0.9 时，任何特征问题的期望收益都有限；应转向“题面复审”（R3）或直接收敛，不要为了“再问一问”而浪费预算。
- **来源**：Wikipedia C4.5 / Information Gain；Codeforces *3 Hard Interactive Problems*（查询要最大化区分）。

### R3 反常回答触发“读题复审”，而不是继续追问算法特征

- **触发**：用户连续答“否/不确定”，或回答与模型预期 KL 差异过大；常见于题面误读或术语歧义。
- **动作**：跳出 grill 状态机，切换到“读题复审”模式：请学生逐字复述“输入、输出、约束、要求什么”；每轮只问一个“这个限制里还有你没用到的条件吗？”，例如“题目说所有边权互不相同，你用到这个条件了吗？”。复审期间**不更新 `P(algorithm)`**，只记 warning 层；复审结束无争议后回到问题流。
- **示例**：学生说“这不是树”，但题面明确写“树 n 个点 n−1 条边”——先用“你确认过 n−1 吗？”把它拉回题面，而不是继续问“是否要二分”。
- **用户话术**：“我们先不猜算法。你把题面里每个限制念给我，我只问你：哪个条件你还没用上？”
- **反例**：当学生确实指向一个冷门但正确方向时，复审不能变成“追问到承认错误”；保留“我感觉不对劲”出口。
- **来源**：Shute *Focus on Formative Feedback*（反馈要对准误区来源）；Codeforces *Characteristics of the optimal solution*（先确认题目观察）。

### R4 专家分歧三分支台账：保留条件分支，不揉平均值

- **触发**：两条专家原语冲突（A 主张 X，B 主张 Y），需要合并进共识。
- **动作**：建立三列：`A 主张 / B 主张 / 两者都成立的条件`。输出**两个** primitive，各自带 `condition` 与低 `agreement`；概率矩阵保留两个分支，不取平均；若条件字段为空且只是用词不同（“先暴力” vs “先 naive”），则合并为一条。
- **示例**：A“先构造”，B“先搜索”。条件：当题目只要“任意可行解”且规模小 → 先构造随便给解；当要求“最小/最优”且直接构造困难 → 先搜索/判定。两个分支都保留。
- **用户话术**：“两位高手在这里不是冲突，是各管一种情况。我们先把情况分开，再分别记一条。”
- **反例**：把分歧当噪音删掉，或为了“共识感”强行平均成 50%——这会删除本该保留下来的条件信息。
- **来源**：Codeforces *Characteristics of the optimal solution*；本技能“共识分级”节（local convention，明确保留分歧不平均）。

### R5 训练反馈三段式：必须给出可执行下一步和反证条件

- **触发**：学生做完题、看完题解、或模拟赛后需要反馈。
- **动作**：每条反馈必须包含：①**卡点**（具体到某个原语/步骤，不打算法名）；②**可执行下一步**（例如“把 n=3 的手算过程写出来”“给当前贪心造一个反例”）；③**反证条件**（“如果出现 X，就放弃当前方向/换另一个原语”）。把每条反馈记入日志，用于统计“哪种反馈后 7 天内同类错误复发率下降”。
- **示例**：不说“贪心不对，用 DP”，而说“你最后一次贪心在哪个输入上会错？请构造一个 3 元素反例；如果构造不出来，就检查你的排序关键字是否满足交换论证。”
- **用户话术**：“我只告诉你下一步做什么，以及出现什么信号就该回头；答案要你自己推。”
- **反例**：“很好/再想想”没有可执行性；直接给完整题解也没有反馈闭环，会跳过学生的检索与自我解释。
- **来源**：Shute *Focus on Formative Feedback*；Ericsson *The Role of Deliberate Practice*；Koedinger *KLI Framework*。

### R6 间隔重做 + 检索练习：掌握度 = 隔周无提示能独立复现

- **触发**：学生刚听完讲解/刚看题解，自认为“会了”；或制定复习计划。
- **动作**：不立即重做，隔 1–7 天不看任何提示重做同一题或相似题；重做前先写“我记得的关键原语”，再写代码；记录是否能无提示复现。掌握度按“隔周无提示能独立通过”计，不按“当时看懂了”计。
- **示例**：学完“双指针”后，第 3 天重做原题，先默写触发条件“窗口右端移动时最优位置是否单调”，再写代码；若只记得“双指针”，算不合格。
- **用户话术**：“今天不评判你懂没懂。过几天我会让你不看书重做一遍，那才算数。”
- **反例**：间隔重做但不核对答案会把错误固化；必须在重做后核对题解/运行结果并做误差分析；完全没有反馈的“纯刷题”不是刻意练习。
- **来源**：Dunlosky et al. *Effective Learning Techniques*；Bjork & Linn *The Science of Learning and the Learning of Science*。

### R7 概率校准日志：先预测、后看标签、算 Brier 与校准曲线

- **触发**：对 primitive 做 OJ 抽样校准或回测，想决定“保留 / 降权 / shadow”。
- **动作**：每条样本先记录预测 `P(feature|algorithm)`，再暴露真实标签；保存 `(p, y)` 对。计算 `Brier = mean((p - y)^2)` 与分桶校准误差。`Brier > 0.25` 或中段校准偏差 > 0.2 时降权或移入 shadow；样本 < 30 时用 Beta 平滑与置信区间，不因单次波动删除。
- **示例**：某 primitive 的 top-1 命中率 90%，但预测概率全部是 0.99，实际正例率 70%——校准误差 0.29，说明过度自信，应降权并检查问题模板是否把“可能”说成“一定”。
- **用户话术**：“我暂时不问你‘准不准’，先问‘你报的数字老实不老实’；过度自信比命中率低更危险。”
- **反例**：只看 top-k 命中率会掩盖过度自信；只看 Brier 又会惩罚样本稀少的冷门方向，必须结合置信区间与 Beta 平滑。
- **来源**：Wikipedia *Brier score*；Koedinger *KLI Framework*（知识成分的可测量评估）。

### R8 原语可迁移性三问：只对“问题结构”有效，不对“题号/算法名”有效

- **触发**：从单一题解/提交记录提取候选 primitive，准备升为 `consensus`。
- **动作**：三问：
  1. 删掉题目特有名词后还剩什么？
  2. 换数据范围/图/序列后还成立吗？
  3. 能否写成“问题结构特征”而不是“算法名”？
  三问全过才标 `consensus`；只过一半标 `style/warning`；完全依赖特定题标 `common-lore` 并降权。
- **示例**：“n=40 用折半”应归入已有“规模决定复杂度 + Meet-in-the-middle”主题，不新增条目；“边数远小于点数时优先考虑树结构”是可迁移原语。
- **用户话术**：“这条规则离开这道题还剩下什么？如果没有剩下什么，它就不是原语，是这道题的答案。”
- **反例**：把“这道题用线段树”当原语，等于背题解；题解记忆不能进入可迁移知识库。
- **来源**：Codeforces *Characteristics of the optimal solution*；Koedinger *KLI Framework*。
