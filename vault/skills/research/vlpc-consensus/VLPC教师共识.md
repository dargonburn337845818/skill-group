# 02 · VLPC 领域教师共识（可载入 Agent 辅导用）

> 本文件按“蒸馏共识”写成：**触发条件 + 动作 + 边界 + 来源 + 用户话术**。
> 目标不是复述论文，而是让 Agent 在辅导时能快速判断“该往哪个方向问、下一步怎么讲”。

---

## 0. 领域一句话

> 可见光定位与通信一体化（VLPC）研究的是：**让同一套 LED 可见光既做室内定位，又做数据传输**。
> 核心矛盾是：一个 LED 的功率/带宽有限，定位要“稳”，通信要“快”，两者如何共用信号而不互相拖累。

---

## 1. 核心共识原语

### 1.1 信号拆分：DC 定位，AC 通信

- **trigger**：看到 VLPC/VLCP 系统，需要同时定位和通信。
- **action**：
  1. 先找接收端如何分离 DC / AC 分量；
  2. 若 DC 用于定位：它携带的是“信道增益/位置指纹”信息；
  3. 若 AC 用于通信：它承载 NOMA 多用户数据。
- **boundary**：如果系统让同一个 AC 分量既承担定位又承担通信，往往计算复杂或精度受限；本文与 Ma et al. 的单 LED 工作走的是“DC 定位 / AC 通信”路线。
- **source_refs**：本文 System Model & Working Principle；S. Ma et al., IEEE TCOM 2023（波形设计）。
- **用户话术**：`先把系统切开看：哪一部分负责“你在哪”，哪一部分负责“传数据”？`

### 1.2 直流信号必须“稳”：双相编码抗消息随机性

- **trigger**：用 DC 分量做定位/信道估计，但数据比特 0/1 随机出现。
- **action**：
  1. 检查是否用编码把“要传的比特”转换为对 DC 无偏的形式（双相编码：0→-1 1，1→1 -1）；
  2. 接收端对多个连续 DC 样本求平均，抑制瞬时噪声。
- **boundary**：这只解决“消息随机性造成的直流漂移”；接收机噪声、LED 非线性、背景光、同步误差仍会引入偏差。
- **source_refs**：本文 Positioning Scheme；Digital Communications 教材（本文参考文献 [8]）。
- **用户话术**：`定位用的直流信号不能随数据抖动，所以要先“编码稳住”，再多测几次平均。`

### 1.3 定位抗噪三步：平均 → 多数投票 → 两阶段

- **trigger**：单次指纹定位结果受噪声/数据库粒度影响，重复定位结果不稳定。
- **action**：
  1. 同一 LED 多次采样平均；
  2. 多轮定位结果取**众数**（出现次数最多的位置）；
  3. 先粗定位缩小范围，再在局部指纹库细定位。
- **boundary**：会增加时延/计算量；指纹库网格间距决定精度下限；环境变化（家具移动、光照变化）会让离线库失效。
- **source_refs**：本文 Positioning Scheme；指纹定位相关文献 [10][11][12]。
- **用户话术**：`一次定位不准没关系，多测几次选“出现最多”的答案，再分粗、细两步找。`

### 1.4 NOMA 通信：按信道强弱排队解码 + SIC

- **trigger**：AC 分量给多个用户做 NOMA 通信。
- **action**：
  1. 信道增益强的用户先解码并做 SIC，把弱用户信号剔除；
  2. 关注 pSIC（理想消除）与 ipSIC（残留干扰）；
  3. 用 GRPA/FPA/NGDPA 等功率分配方案分析速率。
- **boundary**：ipSIC 残留干扰会同时降低总速率与 EE；SIC 顺序、功率系数和信道估计误差耦合。
- **source_refs**：本文 Communication Scheme；NOMA-VLC 文献 [6][7]。
- **用户话术**：`多用户共用同一束光，按信号强弱排队解码；解码不干净（ipSIC）就会互相干扰。`

### 1.5 总功率固定的 DC/AC 权衡

- **trigger**：系统总电功率固定，DC 用于定位、AC 用于通信。
- **action**：
  1. 写出 `Pmax(Idc²) = min{ Idc²/K, Ptotal − Idc² }`；
  2. 通信最优点在 `Idc² = K/(K+1)·Ptotal`；
  3. 超过该拐点后，继续加大 DC 会挤占 AC，需在定位精度与通信性能之间取舍。
- **boundary**：解析最优值基于理想线性 LED 模型；实际 LED 非线性、背景光、同步误差会使拐点偏移。
- **source_refs**：本文 Optimal DC Power Setting；仿真结果 Fig. 6。
- **用户话术**：`总功率就一盆水：给定位的直流多了，给通信的交流就少；存在一个让通信最好的拐点。`

### 1.6 定位本质：用光强/信道增益反推位置

- **trigger**：读 VLPC/VLP 定位部分，想理解精度规律。
- **action**：
  1. 建立信道增益与用户位置的函数关系；
  2. 接收端由 DC 信号估计信道增益；
  3. 在指纹库中搜索使误差函数最小的位置。
- **boundary**：定位误差随高度变化不是单调的（本文呈倒 U 形）；角落误差大、房间中心误差小；LED 越多越准。
- **source_refs**：本文 System Model/Positioning Results；[12] 实验。
- **用户话术**：`定位就是“看收到的光强，反推你在哪”；房间中心信号均衡，角落容易测偏。`

### 1.7 精度-复杂度：指纹+投票 优于 元启发式

- **trigger**：对比不同定位算法的精度和运行时间。
- **action**：
  1. 本文定位复杂度约 `O(M(Nc+Nf))`，无迭代优化；
  2. 通信模块最优功率为解析解，复杂度 O(1)；
  3. 与 AC 定位 + WOA/HBA/GA/SSA/BA 相比，在 4cm 精度下本文更省时。
- **boundary**：元启发式可能更灵活、不需要离线指纹库；本文依赖指纹库，误差受网格间隔限制。
- **source_refs**：本文 Computational Complexity Analysis、Table II。
- **用户话术**：`同样做到 4 厘米精度，查表+投票比元启发式搜索快，但代价是提前建指纹库。`

## 2. Agent 辅导用户的提问协议

> 原则：**一次只问一个高信息增益问题**。不要一次抛一串术语。

### 第一步（确认读懂）

问：`这个系统把 LED 信号分成了哪两部分？分别用来做什么？`

- 答对 → 进入第二步。
- 答不出 → 先让他看 Fig. 2，不要继续往下讲公式。

### 第二步（定位链路）

问：`如果直接用接收到的直流值定位，数据比特 0/1 随机出现会带来什么问题？`

- 引导：直流漂移 → 双相编码 + 平均。
- 追问：`单次定位仍然受噪声影响，论文用了哪两步来救？`
- 引导：多数投票 + 两阶段指纹。

### 第三步（通信链路）

问：`多用户 NOMA 解码时，谁先被解出来？为什么？`

- 引导：信道强的先解，做 SIC。
- 追问：`如果 SIC 不完美，速率和能效会怎样？`
- 引导：ipSIC 残留干扰 → 速率/EE 下降。

### 第四步（系统级权衡）

问：`总功率固定时，为什么要专门找一个“最优直流功率”？`

- 引导：DC 给定位，AC 给通信；直流太大挤占通信，太小定位不准；存在拐点。

### 第五步（实验结果）

问：`论文的实验误差约 13 cm，这个误差主要来自哪里？`

- 引导：指纹库网格间距/空间分辨率，不是算法本身失效。

## 3. 常见误读（反例）

| 误读 | 澄清 |
|---|---|
| 认为“LED 越多一定越好” | 本文结论是定位精度随 LED 数量增加而提升，但也要看高度、位置、总功率约束。 |
| 认为“用户越高越好定位” | 本文定位误差随高度呈倒 U 形，不是单调。 |
| 认为“DC 功率越大越好” | 总功率固定时，DC 功率超过拐点会挤占 AC，速率和 EE 反而下降。 |
| 认为“ipSIC 只是小问题” | 本文量化显示 ipSIC 会同时降低总速率与 EE，且随残留干扰因子增大更明显。 |
| 认为“指纹定位不需要离线库” | 本文方法依赖离线指纹数据库；实验误差受网格间隔限制。 |
| 认为“元启发式一定更差” | 文中只是说在 4cm 精度目标下本文更快；并非所有场景都更优。 |
