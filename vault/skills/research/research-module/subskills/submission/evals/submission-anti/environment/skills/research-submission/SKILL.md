# research-submission · 科研投稿（选刊 / cover letter / rebuttal）

> 定位：这是 research-module 的投稿流程子技能。它给的是**可执行的动作与检查点**，不是“保证录用”的承诺。
> 硬性纪律：所有投稿结果类陈述（录用、影响因子、审稿时长、接受率）必须可回溯到公开来源或标 `[待核实]`；不伪造实验、不算命、不替主办方承诺。

## 触发条件

- “我该投哪个期刊/会议？”
- “帮我写 cover letter / 投稿信。”
- “审稿意见回来了，怎么回复？”
- “被拒稿了，下一步怎么办？”
- “这篇改完投哪里更合适？”

## 主流程（四步）

```text
A. 选刊/会议匹配  → 先想清楚“这篇工作适合谁读”
B. Cover Letter   → 用一页说清“为什么这里、为什么值得”
C. Response to Reviewers → 逐条回应，改在哪、为什么、证据是什么
D. 拒稿处理       → 不急着逃，也不急着吵；分类反馈、找下家、可改就改
```

每完成一步都要回到用户确认：**你提供的事实/数据/作者信息是否完整**；缺材料时用占位符，不要编。

## A. 选刊 / 会议匹配

### 输入（先问清这几项）

- 论文类型：研究论文 / 综述 / 方法 / 系统描述 / 短文 / 扩展摘要？
- 核心贡献：一句话说清“解决了什么、对谁有用”。
- 目标读者：本领域同行？交叉学科？工程实践者？
- 硬约束：时间线（投递/通知/会议日期）、经费（APC/注册/差旅）、语言、作者单位与署名。
- 已有线索：参考文献投在哪、导师/团队常投哪、领域内认可的 venue。

### 动作清单

1. **建候选池**
   - 从参考文献反查：引用过的期刊/会议通常是同主题聚集地。
   - 用数据库/检索入口：Scopus、Web of Science、IEEE Xplore、DBLP、Google Scholar、Crossref、期刊/会议官方站。
   - 出版商工具可作起点（如 Elsevier JournalFinder 按摘要推期刊），但要自行核对 aim & scope。

2. **查“适合度”**
   - 读目标期刊的 **Aims & Scope**，或会议的主题/分会场（tracks / topics）。
   - 看最近 1–3 年发表的相似文章：主题、深度、文章类型、是否接受你的贡献形态。
   - 检查 Guide for Authors / Call for Papers：格式、页数、参考文献风格、字数、投稿系统、是否开放获取/专题征稿。

3. **查“可信度”**（Think. Check. Submit. 期刊检查表核心问题）
   - 刊名是否唯一、是否能在 **ISSN Portal** 查到？
   - 出版商名称、联系方式是否清楚可查？
   - 是否写明**同行评审类型**（独立外部评审、每篇几位评审）？
   - 是否会保证录用或“极短审稿时间”？**会，就是危险信号**。
   - 是否被可信数据库索引/长期存档/使用持久标识符（DOI）？
   - 费用是否透明：收什么费、何时收、币种、是否有 waiver？
   - 版权/许可是否清楚；是否允许自我存档/机构库共享？
   - 有无利益冲突政策；是否 COPE 成员；OA 期刊是否在 DOAJ；是否 OASPA 等。
   - 会议还要看：是否 IEEE/ACM/Springer 等正规出版；是否 faked“IEEE 赞助”；是否有真实既往论文集/索引。

4. **做取舍矩阵**
   - 给每个候选 venue 打分：`适合度 / 可信度 / 时间线 / 成本 / 目标读者到达度`。
   - 明确“如果只允许投一版，先投哪个、备选哪个”。
   - 记录结论：为什么选它、为什么放弃它。

### 边界

- **不承诺录用**；接受率、影响因子只是参考，不是论文价值的裁判。
- 不“唯影响因子/分区”选刊；要看是否真正被目标读者读到。
- 不把声誉差、收费不透明、自称“快速录用”的 venue 列入候选；宁可少投，不可投错。
- 会议匹配 ≠ 只看 CFP 标题；要看 track 是否真的接受你的贡献形态。

## B. Cover Letter（投稿信）

### 结构化骨架（源自 Springer / Elsevier 官方指南）

```text
1. 抬头
   日期、目标期刊/会议名、编辑姓名（若知）、投稿系统所需题头。

2. 第一段：这是什么
   论文标题 + 文章类型（研究/综述/方法/案例等）
   背景与想回答的问题：为什么做这个研究。

3. 第二段：做了与发现
   做了什么、主要发现、为什么重要。
   只写已经完成并有证据的结果，不写“将要做”“预计”。

4. 第三段：为什么适合这里
   解释研究如何契合期刊/会议 aim & scope。
   说明对目标读者的价值：谁会感兴趣、为什么。

5. 收尾（按期刊要求）
   声明：本稿未在其他刊物发表或同时投稿中；
         所有作者已阅读并同意投稿；
         通讯作者信息；
   如有邀请投稿（invited）、与编辑先前讨论、相关稿件同时处理中，按 Guide for Authors 说明。
```

### 快速检查

- [ ] 一页以内，聚焦，不复制摘要整段。
- [ ] 明确点出**研究目标 + 主要发现 + 为什么适合该刊**。
- [ ] 提到被邀请等情况（若有）。
- [ ] 不含 funding、author declarations、推荐/回避审稿人等信息——**除非 Guide for Authors 明确要求**（Elsevier 明示这些应在单独表格/系统里，不写进 cover letter）。
- [ ] 不编造 novelty 或影响；“potential impact”要说清证据链。
- [ ] 检查各期刊具体要求，因为不同期刊差异很大。

### 边界

- Cover letter 不是 mini-paper；不要贴整段方法/全部图表。
- 不写“保证有影响力/保证引用”之类空话。
- 不对期刊/编辑做不实承诺；不隐藏“一稿多投”状态。

## C. Response to Reviewers（回复审稿意见 / rebuttal）

### 开始前

1. **先冷静，不当天回**：读完全部意见，隔一段时间再复述“审稿人到底要我做什么”。
2. **分类**：`major` / `minor` / `clarification` / `out-of-scope` / `factual error`。
3. **对照正文**：每条意见在稿件哪里、需要动什么（正文/图/表/补充材料/新实验）。
4. **如果不能做**：想清楚是“不做”（有充分理由）还是“做不到”（需要额外资源），并准备与编辑沟通。

### 回复文档结构（Nature Computational Science 推荐）

```text
0. 开头摘要
   总结审稿人的主要关注点 + 本轮做了什么修改。
   让编辑/审稿人第一眼看到“变化在哪”。

1. 逐条回应
   把审稿人原文完整贴上，不要省略选择性回应。
   紧跟作者回复，并明确区分（颜色/加粗/引用框/字体均可）。

2. 每条回复至少包含
   - 审稿人问题（原文）
   - 作者判断：接受 / 部分接受 / 不同意
   - 修改动作：改到正文哪个位置（章节/行号/图/表/补充材料）
   - 证据：数据、引用、解释；必要处贴更新后的文本或新图
```

### 回复质量规则

- **不要只写“已修改”**：说明怎么改、改在哪。
- **不同意要讲证据**：礼貌陈述科学理由，引用数据/文献/方法；不是“审稿人不懂”。
- **新证据必须进正文或补充材料**：不能只在 response 里出现。
- **无法完成的要求**：说明为什么，必要时与 handling editor 讨论，不要硬编。
- **尊重并专业**：不贬低审稿人；可以指出事实性错误，但要礼貌且用证据。
- **给编辑省时间**：Cover letter + Response list + Track changes 版 + Clean 版，一起提交（CALM 四件套）。

### 边界

- 不伪造/补做不存在的实验；不删除不利数据。
- 不为了“显得回应充分”把无关内容塞进 response。
- 不把审稿意见当敌人；分歧保留但必须清晰。
- 不承诺“下轮一定改”而不落实。

## D. 拒稿处理

### 第一步：分类原因

- **Desk rejection（未送审）** 常见原因：不在 scope、语言/结构问题、不符 Guide for Authors、novelty/impact 不足、伦理问题（Elsevier 经验总结）。
- **Post-review rejection**：通常决策信会说明。方法缺陷、分析异常、实验不可复现是**必须在下次投稿前修掉的**。
- **编辑/审稿人误解**：如果确实是事实性误解，可在下个 venue 的 cover letter 或与编辑沟通中澄清，但不要因此攻击原审稿人。

### 第二步：决定路径

| 情况 | 动作 |
|---|---|
| 有明确可修问题 | 先修 major/minor，再投新 venue |
| 只是 scope 不合适 | 找更匹配 venue，可考虑 transfer offer |
| 语言问题 | 找母语者/语言编辑服务，先过语言关 |
| 新证据不可补 | 重新定位贡献/局限性，降低过度声称 |
| 想申诉（appeal） | **非常谨慎**：除非编辑邀请或有明确程序/事实错误，否则大多数申诉不会成功；别把“我们改好了”当申诉理由 |

### 第三步：找下家

- 参考文献里出现过且 scope 匹配的期刊/会议。
- 数据库/出版商工具：Scopus、IEEE Xplore、DBLP、Elsevier JournalFinder、会议官方历届论文集。
- **Transfer offer**：若原期刊提供转移推荐，评估 scope/时间后可用，能省重投工作量。
- 不要直接原封不动投另一家：先修内容、格式、cover letter 重新针对性写。

### 边界

- 拒稿不是对人格的否定；反馈是改进材料。
- 不因“被拒”就降低标准投到可疑期刊。
- 不保证“换一家必中”；只降低明显可修的风险。
- 不把被拒稿件的反馈原样复制到新投稿中；要重新检查与目标 venue 的匹配。

## 反模式速查

| 反模式 | 正确做法 |
|---|---|
| “这个期刊影响因子高就投它” | 先看 aim & scope、可信度、时间与成本；接受率只作参考 |
| Cover letter 里堆摘要 | 一页说清为什么、发现了什么、为什么适合这里 |
| Rebuttal 里只写“已修改” | 说明改在哪、怎么改、证据是什么 |
| 选择性跳过审稿意见 | 逐条完整回应；不同意的也要给理由 |
| 新数据只在 response 里展示 | 必须进正文或补充材料 |
| 被拒后直接原样投下一家 | 先分类原因、修问题、重写针对性 cover letter |
| 保证录用/影响/引用 | 只给可核验事实，不确定标 `[待核实]` |
| 把未 ready 专家当权威 | 标 pending_distill，或换用 ready 专家 |
