# 模拟导师审查 · Mentor Review

## 触发

- 论文/项目投稿前、组会汇报前、开题/中期/答辩前想先被“导师团队”拷问。
- “帮我模拟导师审查”“如果导师们看这个工作会问什么”。

## 动作

1. **确定导师团**：从 `EXPERT_LIBRARY.json` 选择 ready 导师；用户可指定人选；无 ready 导师走专家缺口分支。
2. **学生汇报**：让用户给出 2–5 分钟口述摘要（背景 / 问题 / 方法 / 结果 / 下一步）。
3. **各导师提问（回合式）**：
   - 每轮一位导师，只问一个当前最重要的问题；
   - 问题必须可回答，且能区分“理解不到位”还是“工作本身有缺口”；
   - 记录 `expert_id`、`expert_name`、问题、为什么问。
4. **问题点/创新点汇总**：

```text
问题表：问题 | 提问导师 | 严重度 | 证据/依据
创新表：创新点 | 支撑证据 | 哪位导师认为值得深挖 | 风险
```

5. **建议下一步**：按优先级给出 1–3 条短期行动，每条标注导师姓名与理由。
6. **冲突与裁决**：导师之间意见冲突时，列冲突表，交给用户裁决（采纳/保留/驳回）。

## 边界

- 模拟审查是“预演”，不是真实评审结论；不能代替导师/审稿人反馈。
- 所有导师意见是风格/方法论推断，不是本人原话，必须保留 sourceRefs。
- 不因“导师觉得有问题”就武断否定工作；用户可保留分支。
- 一次只问一个问题，避免把审查变成术语轰炸。

## 2026 深度补强（Round 33）

主题：提问策略、审查维度、常见漏洞、准备与回应。本轮只补“怎么问得深、怎么答得稳、怎么把隐性标准显性化”，不改变原有“导师团回合式提问 + 问题/创新点汇总 + 冲突裁决”的流程骨架。

### R33-1 审查先设“五维靶”，每问之前先标测哪一维

- 触发：开始正式提问前，不要上来就问“数据从哪来”。
- 动作：把模拟审查的提问面固定为五维：
  1. 贡献与原创性（significant contribution / originality）
  2. 理论/概念（theory / conceptual fit）
  3. 方法严谨性与可复现（rigour / reproducibility）
  4. 批判性与局限性（criticality / limitations）
  5. 学术身份与表达（scholarly identity / communication）
  在问题表里加一列“审查维度”；每轮提问者先说明“这一问在测第几维”，再开口。
- 反例：三位导师都问“实验数据来自哪里”“为什么选这个参数”，全部落在第 3 维，没人测贡献边界、理论一致性或可替代解释。
- 示例：学生说“我们提升了定位精度”时，先问“删掉这部分后论文的核心贡献还剩什么？”（第 1/4 维），再问“误差棒怎么算、是否独立重复”（第 3 维）。
- 依据：De Vita & Begley (2023) 的 “doctorateness” 研究指出候选人对“显著贡献”“理论”常只停在表层理解，对原创性/批判性/严谨性存在一维化看法；external examiner 一章也表明评审标准常是隐性个人标准，需要显性化为共享语言。

### R33-2 问题分四类，按类型决定问法与回答深度

- 触发：每一轮“只问一个问题”时，先给问题定性。
- 动作：把问题分为四类，并采用不同深度：
  - 理解确认题（“你是不是把 A 理解成 B？”）：一句话确认，不展开。
  - 方法正当性题（“为什么这样设计/这样算？证据是什么？”）：先复述假设 → 给证据 → 给限制条件。
  - 贡献边界题（“与已有工作的差异是什么？删掉某部分还剩什么？”）：给“同场景/同指标”差异表 + 一句边界声明，不背 related work 流水账。
  - 范围扩展题（“换到 X 场景会怎样？”）：给可证伪的小实验，不要用“未来可以研究”糊弄。
- 反例：被问“你和已知工作有什么区别”时，开始念整个相关综述；正例：“在同一数据集、同一指标下，我比基线多报告 Y；首次给出 X 场景下失败案例与失效边界，这两点是本次差异的核心。”
- 依据：Bernard & Abramo (2019) 的提问策略章节讨论问题类型、措辞、分层提问与第三轮回应；De Vita & Begley (2023) 则说明“贡献”和“理论”最容易被误解，因此贡献边界题要单独设计。

### R33-3 导师团先“定靶分工”，每人先写一句通过标准

- 触发：正式模拟前用 1 分钟完成，而不是问着问着才发现重复。
- 动作：
  1. 给每位导师分配一个优先维/角色（如方法论守卫、贡献边界、可复现性、理论一致性、表达与听众）。
  2. 每位导师写一句可观察的“通过标准”，例如：“能说出在什么条件下结论失效”“能给出至少一个可替代解释并说明为何排除”。
  3. 把标准写进审查表头；后续冲突裁决时也用它判断“两位导师是否在测同一件事”。
- 反例：三位导师都问“为什么不用 XX 模型”，低信息重复；或者某导师说“我觉得不行”但没有可复核标准。
- 依据：对马来西亚 12 位博士考官的访谈显示，考官“问什么/怎么问”高度情境化且规则隐晦；external examiner 一章强调 assessment literacy 与共享语言，正因隐性标准才需要显性化。

### R33-4 三问框架：边界、可替代解释、贡献纯度

- 触发：听到任何“结果好”“创新点”“首次提出”之后，至少补三问。
- 动作：
  1. 边界问：“你的结论在什么条件下成立，什么条件下不成立？”
  2. 替代解释问：“如果不是你解释的机制，还有哪个混杂因素/测量偏差/其他机制也能产生相同结果？你如何排除？”
  3. 贡献纯度问：“如果去掉本工作的某一部分，核心贡献是否消失？哪些部分是必要件？”
- 反例：只问“为什么结果好”，不挑战可替代解释；只问“创新点是什么”，不问“删掉后还剩什么”。
- 示例：对“我们比基线高 10%”追问：“这 10% 是随机波动还是系统差异？100 次独立实验中请给出置信区间；若换成另一组多径条件，是否仍成立？”
- 依据：De Vita & Begley (2023) 的批判性/严谨性维度；Bernard & Abramo (2019) 的提问措辞策略，强调问题要能引出分层证据而非口号。

### R33-5 候选侧常见漏洞检查表（八项）

| 漏洞 | 反例说法 | 可执行修正 |
|---|---|---|
| 贡献真空 | “我做了 A+B+C” | 改用贡献句：“在 X 约束下，相对 B，A 使 Y 提升 Z（n 次独立实验），并首次报告 W 的失败边界。” |
| 只报成功 | 只展示最好一组结果 | 额外准备“我们试过什么、为什么不行”一节；负结果也是证据。 |
| 黑盒方法 | 被问实现细节答“用了网络，效果不错” | 给每个模块写“输入 / 输出 / 关键参数 / 失败模式”一句话卡。 |
| 未来当成果 | “未来可以扩展到……” | 明确区分已做 / 部分做 / 未做；未做的不写进贡献表。 |
| 不区分理解与缺口 | “我没想过，应该不重要” | 先承认是理解缺口还是工作缺口；若是理解缺口，补读后回答；若是工作缺口，记入下一步。 |
| 过度防御 | 被质疑立刻辩解“你理解错了” | 先“我确认你问的是……”再分层回应；不争辩、不贴标签。 |
| 不做边界 | “我们的方法普遍适用” | 主动说适用条件与失效条件；越早说出边界，越显批判性。 |
| 不接反馈 | 收到意见只改字面、不改实质 | 每条意见给“采纳 / 部分采纳 / 不采纳 + 证据”三列回应，并落到具体行动。 |

- 依据：Mortell (2024) 建议用模拟与议程清单准备；Lantsoght (2022) 显示 mock defense 是最有效准备方式；关于“主动接反馈”，Examiner Feedback and Australian Doctoral Examination Processes 一文强调候选人需要在收到审查意见后主动参与整改，而不是被动等待结果。

### R33-6 回应五步协议：复述-分层-证据-边界-后续

- 触发：被导师问到任何一个问题时，先不要急着“背答案”。
- 动作：
  1. 复述：“你问的是不是……？”确认问题落在哪一层（理解确认 / 方法正当性 / 贡献边界 / 范围扩展）。
  2. 分层：一句话给答案 → 再给证据 → 再给限制。
  3. 证据：优先引用论文图表、实验编号、可复现命令、公开文献；没有就说没有，不编。
  4. 边界：明确“这部分目前没有直接证据，我基于……推断”。
  5. 后续：被问倒时给“我会查证 X / 补做 Y 实验”，并把该条记入下一步；不装懂、不转移话题。
- 反例：“应该吧，大家都这么用”或“这个问题不影响我们的结论”都属于无边界回应；正例：“在我的设置 A/B 下成立，10 次独立实验均得出……；但换到场景 C 我没有验证，所以只能说在 A/B 下成立，C 是待证。”
- 依据：Mortell (2024) 的 viva 经验与模拟建议；Moosa et al. (2020) 的虚拟 viva 教练系统强调用可重复练习降低恐惧、训练“被追问”时的表达；主动接反馈部分参考 Australian examiner feedback 研究。

### R33-7 准备用“四列卡 + 故意卡壳”，mock defense 优先

- 触发：用户说“我已经把答辩稿写好了”，先不要夸，先检查有没有 mock 过。
- 动作：
  1. 为每个预期问题做四列卡：问题 | 一句话答案 | 证据锚点 | 待证。
  2. 只写关键词、不写逐字稿；用口头演练代替背稿。
  3. 至少做一次 mock defense；mock 后专门记录“被追问到卡壳”的点，并逐一补证据或降级为“待证”。
  4. 优先级：mock defense > 预备课程 > 读博客/书（证据强度来自 Lantsoght 2022 及其预印本：mock 最有效，读博客/书相对低效）。
- 反例：写完 3000 字逐字稿并背诵，被追问一句就崩；或只收集“常见问题清单”不看自己的实验细节。
- 依据：Lantsoght (2022) 与预印本 (2021) 都报告 mock defense 是最有效准备措施；Moosa et al. (2020) 的虚拟 viva 教练说明可重复练习对缓解畏惧、提升表达有价值。

### R33-8 先查“本校本领域的结果类型与流程”，再定模拟目标

- 触发：开始模拟审查前，先确认这不是“过/挂”二元游戏。
- 动作：
  1. 列出可能结果：通过、小修、大修、改写后重提、降级授予（有/无重提）、不通过。
  2. 查学院/学科规则：每类结果的时限、复审路径、申诉渠道、是否需要重新答辩。
  3. 若模拟目标是“应对大修”，就把重点从“如何说服”改成“如何把批评转成逐条整改计划”。
- 反例：默认答辩只有“通过/不通过”，没有准备“如果导师要求重写第 3 章 / 补 2 个实验”的回应与排期。
- 正例：提前查清规则后，模拟审查表额外加一列“若该问题导致大修，整改第一步是什么、预计多久、谁复核”。
- 依据：van Teijlingen et al. (2022) 指出不同院校/学科在“通过、改写重提、降级、不通过”内部还有大量细节差异；Fleming & Kowalsky (2021) 专门列出可能的口试结果；Lantsoght (2022) 的结论也强调考生要先理解本场 defense 的格式与规则。
