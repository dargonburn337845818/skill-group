# 模拟导师审查 · Mentor Review

## 触发

- 论文/项目投稿前、组会汇报前、开题/中期/答辩前想先被“导师团队”拷问。
- “帮我模拟导师审查”“如果导师们看这个工作会问什么”。

## 动作

1. **确定导师团**：从 `EXPERT_LIBRARY.json` 选择 ready 导师；用户可指定人选；无 ready 导师走专家缺口分支。
2. **学生汇报**：让用户给出 2–5 分钟口述摘要（背景 / 问题 / 方法 / 结果 / 下一步）。
3. **各导师提问（回合式）**：
   - 每轮一位导师，只问一个当前最重要的问题；
   - 问题必须可回答，且能区分“理解不到位”还是“工作本身有缺口”；
   - 记录 `expert_id`、`expert_name`、问题、为什么问。
4. **问题点/创新点汇总**：

```text
问题表：问题 | 提问导师 | 严重度 | 证据/依据
创新表：创新点 | 支撑证据 | 哪位导师认为值得深挖 | 风险
```

5. **建议下一步**：按优先级给出 1–3 条短期行动，每条标注导师姓名与理由。
6. **冲突与裁决**：导师之间意见冲突时，列冲突表，交给用户裁决（采纳/保留/驳回）。

## 边界

- 模拟审查是“预演”，不是真实评审结论；不能代替导师/审稿人反馈。
- 所有导师意见是风格/方法论推断，不是本人原话，必须保留 sourceRefs。
- 不因“导师觉得有问题”就武断否定工作；用户可保留分支。
- 一次只问一个问题，避免把审查变成术语轰炸。
