# 本地素材盘点（Local Material Inventory）

> 用途：为「UI 美学设计 Skill」识别工作区内可作旁证、样例或反例的既有素材。
> 记录约定：路径 / 可贡献点 / 局限 / 用途。
> 重要边界：**本地素材只作补充语料，不是唯一权威来源**；单一风格、单一项目、第三方素材均需降权，最终以多源公开规范 + 一手研究交叉验证。

## 一、素材清单

### L1-editorial-style-spec
- 路径：`$WORKSPACE/editorial-style-spec.md`
- 可贡献点：
  1. 一套完整、可执行的“单风格”设计规范：标题衬线 + 正文无衬线、字号阶梯（hero/H1/H2/H3/正文/小字）。
  2. 用透明度（`/60 /40 /10`）做单色层级：`#1C1C1C` 配合不同透明度构建视觉层次。
  3. 间距与留白尺度：section `py-16 md:py-24 lg:py-32`、容器 `px-6 md:px-12`、卡片 `p-6`、gap 4/6/8 等。
  4. 明确的反模式清单：`FORBIDDEN` 禁止圆角/阴影/粗边框/彩色/渐变；`REQUIRED` 按钮、卡片、输入框必须包含的 class。
  5. 正反对照（WRONG vs CORRECT）可学“如何写风格规范”。
- 局限：
  - 只代表“Editorial 编辑杂志风”这一种风格，不是通用美学标准。
  - 部分规则（无圆角、无阴影、单色）是风格选择，不是普适设计铁律；不能写入本 Skill 的共识层。
  - 未提供真实用户测试/无障碍验证，不能作为可访问性证据。
- 用途：作为“风格化设计规范”样例与反例素材；可提取“字体对比、单色层级、间距尺度、禁止项”等可迁移方法。

### L2-stylekit-editorial
- 路径：`$WORKSPACE/stylekit-editorial.html`、`$WORKSPACE/stylekit-editorial.txt`
- 可贡献点：
  1. 完整单风格 token：`Primary #1C1C1C`、`Secondary #F9F8F6`、Accent 色阶与透明度用法。
  2. 结构化 FAQ 提炼了“怎么把风格做对 / 常见错误”：禁止彩色强调、禁止阴影/粗边框、避免纯黑 `#0a0a0a` 与冷白 `#fafafa`。
  3. “硬性提示词 / Design Spec / Creative Brief”三段式，可作为“风格包装”的参考结构。
  4. 页面自带完成度评分（如 59/100），提示“风格库评分只是参考，不替代真实设计判断”。
- 局限：
  - 第三方开源风格库（StyleKit）的单一风格条目；不是权威设计标准。
  - 页面主要面向“AI 生成前端”，组件级质量未系统验证。
  - 具体 token 是风格专属，不能直接当成通用 UI 美学规则。
- 用途：作为“风格 token 组织方式”和“正反例提示词”的参考；作为“单一风格边界”的反例提醒。

### L3-ai-ppt-skill
- 路径：`$WORKSPACE/ai-ppt-skill/`（入口 `SKILL.md`，主题在 `themes/`）
- 可贡献点：
  1. 多主题风格包：`tech-dark`、`editorial`、`government`、`senior` 等，展示“同一套组件结构 + 不同 design tokens”的样式组织。
  2. 版式纪律：1280×720 画布、页边距 60~80px、一页只讲一件事、列表 ≤5 条、金句块最多一条。
  3. 视觉质检流程：无头 Chrome 逐页截图、逐张读图检查“文字溢出/对齐/留白失衡/对比度”。
  4. `editorial.md` 给出具体数值：标题 56px、正文 16px/1.7、卡片 1px 边、无圆角无阴影；`tech-dark.md` 给出相反风格（渐变、圆角 16–20px、发光）。
- 局限：
  - 面向 PPT/演示页，不是通用网页/组件场景；布局约束（单页大标题）不能原样套到 Web UI。
  - 依赖 Chrome + python-pptx，是工具链约束，不是 UI 美学知识。
  - 风格主题来自外部/项目约定，不代表普适标准。
- 用途：作为“多风格 token 系统”样例、版式留白与视觉质检清单的旁证；作为“风格强约束 vs 通用美学”的边界案例。

### L4-dsh-deep-whale-inspect
- 路径：`$WORKSPACE/dsh-deep-whale-inspect/`（`maid-atelier/`、`orca-link/`、`skin-switcher/`）
- 可贡献点：
  1. `orca-link` 体现“全局直角契约”：按钮、输入框、卡片、菜单、弹窗、提示、标签、头像、滚动条统一归零圆角，状态信号正方形化——一种非常强的一致性风格控制。
  2. `maid-atelier` 体现“亮/暗自动切换 + 角色/品牌视觉层”的整站皮肤思路。
  3. 两套皮肤都有明确的许可/署名链（CC BY-NC-SA），提醒 UI 素材必须处理版权与署名。
- 局限：
  - 是 DSH Web GUI 品牌皮肤，非通用 UI 规范；强风格、高装饰，不能当作通用美学标准。
  - 未做通用可用性研究；圆角归零、角色装饰属于品牌表达，不能普适。
  - 本地路径只是仓库/皮肤包，核心 CSS 在构建产物内，未系统抽取为通用 token。
- 用途：作为“强风格一致性”与“主题化边界”的案例；作为“品牌视觉/版权/署名”提醒素材。

## 二、可作样例/旁证的具体设计点

| 设计点 | 来源 | 具体证据 / 可复用动作 | 用途 |
|---|---|---|---|
| 标题层级（衬线标题 vs 无衬线正文） | L1、L3 | 标题 `font-serif`，正文 `font-sans`；Editorial 标题 56px/38px/28px，正文 16px | 正例：用字体族+字号区分层级；反例：正文用装饰字体 |
| 单色透明度层级 | L1、L2 | 只用 `#1C1C1C` 配合 `/60 /40 /10` 做主要/辅助/边框层级 | 正例：单一色相靠透明度制造层次；边界：多色数据图表不适用 |
| 间距尺度与留白 | L1、L3 | Editoral `py-16 md:py-24 lg:py-32`、gap 4/6/8/12；ai-ppt 页边距 60~80px、列表 ≤5 条 | 正例：可复制“统一间距尺度 + 大留白”；反例：页面信息过密 |
| 卡片/边框的克制使用 | L1、L3 | Editorial 卡片 1px `rgba(28,28,28,.1)`、无圆角无阴影；tech-dark 卡片 `rgba(255,255,255,.045)` + 1px 边 + 圆角 16~20px | 正例：边框要轻、有层级；反例：边框/阴影堆砌 |
| 风格强约束（禁止项清单） | L1、L2、L4 | Editorial 禁止圆角/阴影/彩色；orca-link 全局圆角归零 | 正例：风格可用“禁止清单”锁定；反例：把单一风格的禁止项当通用标准 |
| 视觉质检流程 | L3 | 逐页截图 → 读图检查溢出/对齐/留白/对比度 | 正例：把“看起来对不对”转化为可复现检查步骤 |

## 三、边界声明

- 本地素材 == 补充语料。它们大多是**单一风格 / 单一项目 / 第三方风格库**，不是通用设计规范或权威研究。
- 本 Skill 的核心规则仍以 WCAG、设计系统官方文档、NN/g 等一手/多源材料为主；本地素材只用于：
  - 展示“风格化 token 如何组织”
  - 提供正反例与检查清单
  - 提醒版权、署名、风格强约束的边界
- 引用本地素材时，在最终 SOURCES.md 中标注 `local-corpus`，并在使用规则中保留“该条仅代表特定风格”的边界。
