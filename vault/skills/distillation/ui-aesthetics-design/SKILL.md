# UI 美学设计 · 可执行摘要

> 给 agent 的短版：先判断任务，再按检查清单逐项过，最后给“问题 → 规则 → 改进 → 边界”。
> 完整依据、逐条来源与反例见同目录 `CONSENSUS.md` 和 `SOURCES.md`。

## 触发条件

- 用户要“生成一个漂亮的网页/组件/仪表盘/表单”。
- 用户要“审查/改进现有界面，让它更好看、更清楚、更好用”。
- 需要给 UI 配色、排版、间距、层级、控件、焦点态、动效做检查。
- 需要判断一个界面“哪里看起来不对劲、为什么、怎么改”。

## 三步主流程

1. **定场景**
   - 是“从零生成”还是“审查改进”？
   - 是普通产品界面，还是数据密集/品牌强风格/演示页？
   - 有没有指定风格（现代化、杂志风、科技风、极简）？

2. **按清单走一遍**
   逐项检查下面的“快速检查清单”，每项给出“通过 / 不通过 / 不适用”。
   发现问题时，不要只说“不好看”，要说出命中哪条规则、建议怎么改。

3. **收口给结论**
   - 问题：哪几项不达标。
   - 规则：命中哪条（配色/排版/间距/层级/控件/无障碍/反例）。
   - 改进：具体数值或动作。
   - 边界：这个改进在什么情况下不适用。

## 快速检查清单

### 1. 配色与对比
- 正文与背景对比度 **≥4.5:1**；大标题可 **≥3:1**；控件/图标/关键图形 **≥3:1**。
- 不要只靠颜色表达状态；错误/成功/选中要有文字、图标或形状补充。
- 浅色和暗色模式都要测一遍，不要只测其中一种（目前主要来自 Apple 官方指导，后续会继续补充独立来源）。

### 2. 字体与排版
- 正文建议 **16px / 行高 1.5（24px）**；小字不低于 14px；辅助文字可 12px 但不承载核心信息。
- 长段落控制行宽（约 45–75 字符），不要拉满整个屏幕（排版流派观点，非普适；代码/表格不适用）。
- 避免用极细/装饰字体做正文；标题与正文字体对比要克制（这是风格偏好，不是通用铁律）。

### 3. 间距与布局
- 间距用统一尺度（**4/8/12/16/24/32/48**），组件对齐 4px/8dp 网格。
- 相关元素放近、不相关元素放远；用留白分组，不要全靠边框。
- 最重要元素获得更多留白；边框/阴影用于轻量区分，不要堆砌。

### 4. 层级与焦点
- 用大小/字重/颜色/留白/位置制造视觉层级；同一屏尽量 2–3 档强弱。
- 一个屏幕以**一个主导 CTA** 为核心，次要动作降级；若动作同等重要则不硬突出。
- 键盘焦点必须可见且不超时；自定义焦点环建议 **≥2px**、状态间 **≥3:1** 对比（AAA 更强标准，AA 只要求可见不超时）。

### 5. 控件与可发现性
- 可点击元素必须有可识别线索：颜色、边框/底色、大小、位置或平台惯例。
- 静态文本不能长得像按钮；装饰元素不能抢可点元素。
- 按钮/输入框/卡片保持同类同款；同产品内一致，遵循平台惯例（一致性目前主要来自一项研究，建议继续补源）。

### 6. 复杂度与反例
- 删除不支持用户任务的装饰；越少越好，但“少”不是“空”。
- 不要为了极简删掉可点击线索、必要分隔或无障碍信息。
- 不要为了“酷”堆渐变、发光、动画；动效只用于状态反馈，并尊重减少动效偏好（这是设计系统/实践偏好，不是通用铁律）。

## 什么时候别用 / 降级

- **数据密集界面**（表格、仪表盘、监控）：大留白/极简会牺牲密度，应使用紧凑间距与清晰网格。
- **品牌强风格**（如全局零圆角、无阴影、单色）：这是风格分支，不是通用美学；不要把单一风格当普适标准。
- **品牌/VI/Logo 设计**：本 Skill 不负责品牌形象与标识设计。
- **只有单一风格来源时**：不要把 StyleKit/本地皮肤/某本书的偏好当成权威；核心规则要有多源依据。

## 给用户的话术

> 我会先按“对比度、字体、间距、层级、控件、无障碍”逐项检查界面，再告诉你哪里不对、为什么、怎么改；如果某个建议只适合某种风格，我会明确说“这只是风格选择，不是通用规则”。

## 2026 深度补强（Round 35）

> 本轮补充 8 条可执行检查点，覆盖 **数据可视化、控件尺寸、文本重排、动效参数、字体配对、语义色/风格库、色盲冗余编码**。全部来源见 `SOURCES.md` →「Round 35 新增来源」；用法与前文一致：逐项检查，命中就给出“问题 → 规则 → 改进 → 边界”。

### R35-1 图表对比：先灰后彩，再做标注层
- **动作**：先把图表所有序列设为灰阶；只给最能支撑结论的 1 个序列/数值加彩；标题用同色呼应重点；关键事件/百分比用 callout 直接标在图上。
- **反例**：默认多序列彩色 + 图例，观众要来回找“哪个颜色代表哪条”；图上没有一句话告诉观众“应该看哪里”。
- **通过示例**：柱状图全灰，唯一失败任务那根柱用高亮色，标题写“Find bill from May 12 显著更低”并用同色呼应。
- **边界**：若读者需要自己对比所有序列而结论未定，不应预设单一重点；标注层必须基于真实结论，不伪造。
- **来源**：NN/g `Contrast: One of the 3 Cs for Better Charts`。

### R35-2 图表去噪：只留数据墨水，标签优于图例
- **动作**：用 data-ink ratio 判断：删掉不承载信息的轴/网格线/装饰；当数据标签能给出精确值，y 轴和网格线可删；系列标签直接放线上/柱顶，别用图例；减少网格线让直接标签更可读。
- **反例**：Excel 默认图表保留 y 轴、密集网格线、彩色图例，观众需要看图例才能区分三根线。
- **通过示例**：三条线直接在线末端标名字，去掉图例和多余网格，只留一条浅基准线。
- **边界**：若需要判断数量级或读取置信区间，保留必要轴/网格；图例在密集多序列且直接标会互相遮挡时可保留。
- **来源**：NN/g `Clutter-Free: One of the 3 Cs for Better Charts`。

### R35-3 可点目标：≥24×24 CSS px，或满足 24px 间距豁免
- **动作**：所有可点击目标至少 24×24 CSS px；小于 24px 时，用“24 CSS px 直径圆不重叠”检查间距豁免；移动端触控建议至少 1cm×1cm（约 38–45px），主 CTA 更大；把热区扩到元素外（padding/伪元素），不要只点可见小图标。
- **反例**：20px 图标按钮紧挨 4px 间隙，容易误触；或可见按钮很大但实际 hit area 只在文字上。
- **通过示例**：图标按钮 24×24 且间距 ≥8px；表单子操作热区扩到 40px 高。
- **边界**：地图 pin、精确点位等“essential”例外可保留小目标，但应提供等效替代（列表/放大镜）。
- **来源**：WCAG 2.2 `Target Size (Minimum)`；NN/g `Touch Targets on Touchscreens`。

### R35-4 排版可重排：允许用户覆盖行距/字距
- **动作**：文本容器不要写死高度/overflow 隐藏；允许用户在 line-height ≥1.5、段后距 ≥2×字号、letter-spacing ≥0.12em、word-spacing ≥0.16em 时内容不丢失；字号用 rem 支持浏览器缩放；正文用干净字体 + 纯背景，不用花字/纹理背景。
- **反例**：卡片 `height: 48px; overflow: hidden`；正文 12px/1.1，用户调大字后截断；装饰字体做正文。
- **通过示例**：行高/字距用相对单位，调大后文本框自动增高；用浏览器放大 200% 复检。
- **边界**：标题/品牌大字可例外；代码/表格等自有布局另按场景处理。
- **来源**：WCAG 2.2 `Text Spacing`；NN/g `Legibility, Readability, and Comprehension`。

### R35-5 动效参数化：100–500ms，缓动有方向
- **动作**：微交互（勾选/开关）≈100ms；普通移动/弹窗 200–300ms；很少超过 400–500ms；进入用 ease-out（开始快结尾缓），离开用 ease-in；进入可比离开稍长；避免硬切/闪烁、视差滚动绑架；尊重 `prefers-reduced-motion`。
- **反例**：所有 hover 800ms、弹窗 1.2s 滑入；或 50ms 的闪现让人看不清状态变化。
- **通过示例**：开关 100ms 完成位移 + 变色 + 光晕；模态 250ms ease-out 进入、200ms ease-in 离开。
- **边界**：大面积/远距离移动可放宽；品牌展示动画可更久，但阅读/表单界面应克制；有前庭/癫痫风险用户必须能关。
- **来源**：NN/g `Executing UX Animations: Duration and Motion Characteristics`。

### R35-6 字体配对：一个多字重字族优先，装饰体只做标题
- **动作**：优先用同一字族的 Light/Regular/Bold/Italic 建立层级；若走双字体，只给每个字体一个明确角色（标题 vs 正文）；装饰体只用于少量标题/插画，并与中性字体配对；不把两个字体都用于正文；在验证码/账号等场景检查 `1/l/I` 与 `0/O` 是否易混。
- **反例**：页面用到 4 种字体，标题/正文/标签/按钮各不一样；装饰体塞进正文。
- **通过示例**：同一个无衬线字族用 extrabold 标题、bold 小标题、regular 正文、light 标签；只有一个 display 字体用于 hero 标题。
- **边界**：品牌/杂志风格可多字体；但正文可读性优先，装饰体不用于长文本。
- **来源**：NN/g `The Dos and Don’ts of Pairing Typefaces`。

### R35-7 色彩语义化 + 用量比例 + 渐变最低对比
- **动作**：用语义色 token（neutral/brand/information/success/warning/danger/accent）而不是散落裸 hex；调色板限约 3 色，用 60/30/10 分配主/次/强调；同一语义全局同色；渐变/图片背景按“最低对比颜色”检查文本（用户缩放后文字可能落在任意位置），并同时检查 3:1 非文本对比。
- **反例**：一个产品里主按钮有四五种蓝；成功用低饱和浅绿、错误用深红且无图标；文字叠在渐变最亮处对比不足。
- **通过示例**：主按钮固定在 brand token，成功 = 绿 + 图标 + 文字，错误 = 红 + 图标 + 文字；渐变底只在深色区放文字并测最低点。
- **边界**：纯装饰色可自由；低风险展示可放宽，但表单/图表/状态仍应保留非颜色线索。
- **来源**：Atlassian Design System Color；IBM Design Language Color；NN/g `Using Color to Enhance Your Design`。

### R35-8 风格库与色盲冗余编码
- **动作**：引入/借鉴官方设计系统时，复制其“语义 token + 角色”组织方式，不要照搬品牌色号，也不要同一产品混搭多套设计系统；颜色之外必须同时用形状/线型/图案/直接标签做冗余编码，避免同亮度不同色相（尤其红/绿）；小图标/细线不要纯色编码；参考 Okabe-Ito 色盲安全色板并做色盲模拟检查。
- **反例**：一个页面混用 IBM 蓝、M3 紫、Shopify 绿；只有红/绿圆点表达成功/失败；细线图只靠颜色区分三条序列。
- **通过示例**：数据系列用“颜色 + 线型 + 直接标签”，调色板取自色盲安全集合；按钮/状态同时有图标与文字。
- **边界**：风格库不是权威；品牌专色（VI）可以独特，但产品功能界面仍需可辨识；色盲模拟只能用于发现问题，不能替代真实用户测试。
- **来源**：Okabe & Ito `Color Universal Design`；IBM Design Language Color；Atlassian Design System Color。

### 快速对照：本轮反例速查

| 反例 | 命中 | 绕过 |
|---|---|---|
| 图表全是彩色 + 图例 | R35-1/2 | 先灰后彩、直接标签、删 chartjunk |
| 20px 小按钮挨着 | R35-3 | 24px 目标或 24px 圆间距 |
| 固定高度截断文字 | R35-4 | 允许重排、rem、不 overflow 隐藏 |
| 800ms hover / 1.2s 弹窗 | R35-5 | 100–400ms、ease 方向、reduced-motion |
| 4 种字体混用 | R35-6 | 一字族多字重或双字体明确角色 |
| 散落 hex 多套蓝 | R35-7 | 语义 token + 60/30/10 |
| 只靠红绿区分 | R35-7/8 | 图标 + 文字 + 形状/图案冗余编码 |
