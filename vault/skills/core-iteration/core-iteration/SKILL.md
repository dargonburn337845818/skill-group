# 核心迭代元能力（Core Iteration）

> 定位：这是技能库唯一的“价值驱动递归提升”入口。它不暴露十个小 skill，而是按阶段组织内部实现。
> 内部实现：`impl/` 下的 benefit-filter、distillation-consensus、value-iterator、value-validator、value-meta-scheduler、value-effect-audit、return-forensics、inspiration-miner、info-source-adapter、web-research-consensus。

## 触发条件

- 用户要求“把这份材料蒸馏成 Skill / 共识 / 知识节点”。
- 用户要求“继续迭代 / 收敛判断 / 收益回测 / 根因分析”。
- 需要从搜索语料中筛选高优、交叉验证、生成绩效曲线和变更日志。
- 用户说“这版 Skill 是否该停 / 是否有效”。

## 动作（外部可见的统一流程）

1. **定目标**：先确认产出是工作流 Skill、启发式规则、提问协议，还是机器可读 JSON。
2. **搜索与来源**：调用 `search-source` 底座获取 raw_corpus 与来源报告。
3. **过滤**：密度评分（反常识/可操作/可验证），多源交叉验证，输出 verified_high / pending / discarded。
4. **蒸馏**：把 verified 语料切到最小推理单元，产出带 `trace_chain` 的 Node（触发/动作/边界/来源）。
5. **迭代**：比较新旧节点，只有真实“有效新增”才接受；强制变更日志。
6. **校验**：语义位移、缺口重合、编辑步长、边际收益四条硬规则；STOP/CONTINUE。
7. **效果/根因**：有真实任务时回填 effect；收益下降时跑 forensics 定位根因。
8. **调度收尾**：输出收敛报告、收益曲线、最终 Skill、丢弃清单与能力评分。

## 边界

- 没有 verified 证据的“专家说”不能进入核心规则；单源必须降权并挂“单源待证”。
- 本模块是做“认知收益”的，不是日常开发流程；开发/重构走 dsh-skill-router 的开发强流程。
- 如果材料不足 3 条 verified-high，应输出 insufficient_corpus，不要为了交差硬编 Skill。
- 用户说“我感觉不对劲”时停止，允许人工覆盖并记录 override。

## 验收/质量门槛（qualityCriteria）

- 每条规则必须有 source_refs 且三件套齐全（trigger/action/boundary）。
- 核心规则默认要求 ≥2 个独立来源；单源只能降权或作为注脚。
- 不平均分歧：冲突保留分支，不揉成 50% 共识。

## 用户话术

> 我会先把材料拆成可执行判断，再按“来源是否可信、是否真的能改变行为”过滤；只有验证过的高优语料才会变成 Skill 规则，最后给你方向、方式和边界。

## 2026 深度补强（Round 38）

> 本轮的硬增量：把六阶段从“顺序流程”升级为带审计账本、信息价值门、双环反思与探索/利用预算的知识收益闭环。新增来源见 `SOURCES.md`「Round 38 新增来源」。

### R38-1 搜索即记账：PRISMA 式检索账本

- **触发**：进入搜索阶段，或任何一条来源被采纳/排除时。
- **动作**：每次搜索落账本：`query / 入口 / 日期 / 过滤条件 / 命中数 / 选中数 / 逐条排除原因`；缺排除原因的轮次视为“未审计”。过滤前先做负向检索：对每个核心 claim 补一次 `limitations / counterexample / does not` 检索；连续两轮无新独立来源 → 写 `search_exhausted`；只增收同源族 → 写 `coverage_bias`。
- **边界**：账本不是“列了链接”，必须能回答“为什么这条没进 verified”。未写排除原因的高优来源不得宣称已完成搜索阶段。
- 来源：S1、S2、S10。

### R38-2 信息价值门：先问“它会不会改变下一步动作”

- **触发**：benefit-filter 打分前，尤其是“来源很权威但一时用不上”的语料。
- **动作**：按 `决策影响 > 信息增量 > 来源强度` 顺序过滤；凡“即使为真也不改变任何 trigger/action/boundary”的语料进 `low_yield` 或 `pending`，不因“信息密度高”进 verified。高成本采集先做 EVPI 式估算：`预期收益 ≈ 决策改变概率 × 该改变的价值 − 采集/迭代成本`；边际收益为负 → `pending`。
- **边界**：来源强度只决定“是否可信”，决策影响才决定“是否值得蒸馏”，二者不可互相补偿。
- 来源：S3、S4。

### R38-3 蒸馏最小单元 + 杀测试（kill test）

- **触发**：把 verified 语料切成 Node 时。
- **动作**：一个 Node 只承载一个“改变行为的判断”，除 trigger/action/boundary 外，必须加一行 `kill_test`：`若观察到 [现象]，本规则失效`。写不出 kill_test 的 Node 标 `hypothesis`，不得作为核心规则发布；后续轮次把 kill_test 当回归哨兵。
- **边界**：把一段话切成三条“同义不同措辞”的 Node 是扩写不是蒸馏；引用来源不变、行为不变的拆分不计有效新增。
- 来源：S11、S3。

### R38-4 有效新增以“行为差异”计量，不以文字差异计量

- **触发**：value-iterator 比较新旧版本并决定 accept/reject 时。
- **动作**：新版本必须改变至少一个 `trigger/action/boundary/kill_test` 的可观察行为，才可记 `effective_new_count`；变更日志必须列出 `before → after` 行为差异。只新增来源、改写措辞、调整排版 → `cosmetic`，拒绝进入收益曲线。
- **边界**：来源数量、字数、结构美观都不是迭代收益；没有行为差异的轮次写“无增量”，不得包装为“知识更丰富”。
- 来源：S11、S12。

### R38-5 双环校验：不仅验“对不对”，还要验“迭代策略本身是否还成立”

- **触发**：每轮 value-validator 给出 STOP/CONTINUE 之前，以及收益下降做 root-cause 时。
- **动作**：单环检查本轮 Skill 输出是否通过验证；双环再问“用来判断收益/收敛的指标与阈值，是否仍在衡量真实价值？有没有把‘容易跑通’当成‘有价值’？”若发现指标失义（只看文字增量、只看来源数），立即暂停迭代并重定义 metric，再继续。
- **边界**：指标失义时继续迭代会放大伪收益，禁止“先跑下一轮再修指标”。
- 来源：S6、S8。

### R38-6 探索/利用预算：调度器显式分配行动预算

- **触发**：value-meta-scheduler 规划一轮行动前。
- **动作**：先定预算，例如 `60% 深化高收益簇 / 20% 探索相邻源与反例 / 20% 验证与红队已有规则`；若同一来源族连续两轮占优，强制调高探索份额。停止条件不是“没有新想法”，而是“继续探索的期望新增收益 < 当前成本”，以连续 2 轮无有效新增为硬下限；探索失败要记 `exploration_empty`，不能悄悄忽略。
- **边界**：探索是成本不是美德；预算分配本身也要进审计包，否则无法区分“收敛”和“放弃”。
- 来源：S7、S8。

### R38-7 审计包：来源→决策→产物→效果一条链

- **触发**：每轮收尾或用户要求审计时。
- **动作**：落盘最小审计包：`search_ledger / filter_rationale / accepted_nodes / rejected_nodes / behavior_diff / eval_fingerprint / stop_reason`；若无法从 trace_chain 回答“为什么这条规则存在”，视为未完成。每条规则标注来源类型：`primary`（一手/官方）、`derived`（二手/综述）、`analogy`（类比/启发）；`analogy` 不得伪装成 `primary`。
- **边界**：审计不是事后补写；先跑流程再补账本 = 伪造证据，应予回退。
- 来源：S9、S5。

### R38-8 伪收益反例表（见到即打回）

| 现象 | 判定 |
|---|---|
| 10 个 URL 来自同一通稿/同源族 | 只算 1 个来源 |
| 新增 5 条来源但 trigger/action 一个没变 | cosmetic，不计收益 |
| “我觉得更全面了” | 无行为差异，不成立 |
| 只记录被采纳的，不记录排除的 | 审计缺失 |
| 连续几轮只重读旧 Skill 直到“顺眼” | 不是迭代 |
| 先写结论再补来源 | 证据链不可信，回退 |
| 停止原因是“今天没搜到新的” | 不是收敛，须用边际收益判据 |
| 校验只给 LLM judge 分，无确定性 oracle | 诊断非门禁 |

- 来源：S12、S2、S7。
