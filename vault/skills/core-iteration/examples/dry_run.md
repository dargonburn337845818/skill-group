# 干跑样例：3 个典型场景

> 这些样例用于校验 skill 是否可执行。每个样例都演示：拆问题 → 检索 → 核验 → 交付，以及边界。

## 场景 1：核实一句网络传闻

**用户问题**：“网上说某公司产品有安全问题，真的吗？”

**拆问题**：
1. 原始通告/官方声明是什么？
2. 第三方审计/报道是否独立？
3. 最近更新时间是多近？

**检索动作**：
- `"公司名" 安全漏洞 官方声明`
- `site:公司域名 安全公告`
- `公司名 安全 advisory filetype:pdf`
- 换英文关键词/换 `site:` 到安全机构。

**核验动作**：
- 回到厂商官方安全公告原文，看发布日期与影响范围。
- 找 2–3 个独立信源（安全媒体、CVE 数据库、第三方研究），并确认不是同一篇通稿。
- 若页面已删，用 Wayback Machine 查公告存档。

**交付**：
> 方向：先看厂商官方公告和 CVE 条目。方式：核对发布日期、影响版本、修复方式；再找独立安全媒体交叉验证。边界：只有一篇转发贴不能下结论；官方公告也可能滞后，需看第三方是否复现。

## 场景 2：查一篇“记得的论文”

**用户问题**：“我记得有篇论文说某方法有效，你帮我找找。”

**拆问题**：
- 作者/年份/标题/期刊/关键词有哪些？
- 是同行评审论文、预印本，还是博客？

**检索动作**：
- 用作者 + 标题片段 + 关键词查 Google Scholar、PubMed / arXiv、出版社官网。
- 用 `"标题短语"` 精确定位。
- 查引用它的综述，确认该方法是否被后续独立验证。

**核验动作**：
- 打开论文摘要/全文，确认确实支持用户想要的结论（而不是只相关）。
- 检查是否被撤稿、是否在掠夺性期刊、是否是预印本未同行评审。
- 不确定时写“找到了 X，但它只是预印本/综述转述，需再核验”。

**边界**：
- 模型“记得”的论文可能不存在、被撤稿或张冠李戴；没有实际检索并打开原文，就不算可靠引用。

## 场景 3：验证一张图片/视频来自哪里

**用户问题**：“这张图是真的现场照片吗？”

**拆问题**：
- 图片首次出现在哪？发布时间？地点？
- 是否有 EXIF/元数据可用？
- 是否与已知事件匹配？

**检索动作**：
- 反向图片搜索（Google Lens / Yandex / TinEye）。
- 搜文字/场景关键词 + 地点 + 日期。
- 视频用拆帧后反向搜关键帧。

**核验动作**：
- 对比原发时间、地点、光线/阴影/地标。
- 查是否有同一图片被早先用于不同事件的报道。
- 若无法确认，写“目前只能确认图片存在，不能确认原创/时间/地点”。

**边界**：
- 反向图搜只证明“网上有同图”，不能证明它是真的或是现场。
- 生成式图片可能反向搜不到或匹配到错误上下文。

## 交付时统一话术

> 我给你的是三样东西：方向（先回一手/原始出处）、方式（拆分问题 → 精确检索 → 独立核验）、边界（什么时候不能下结论）。如果哪条和你的直觉冲突，请说“我感觉不对劲”。
